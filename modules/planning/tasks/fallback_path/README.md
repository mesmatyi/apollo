planning-task-fallback-path
==============

## Introduction
`FallbackPath` is used to generate a fallback path when the preceding tasks in a stage did not generate a path. This task generates the path only from the lanes and the vehicle pose and does not consider road obstacle information; obstacle information is handled in speed planning. The task obtains the ego vehicle position through `Frame`, obtains the lane information and reference line information through `ReferenceLineInfo`, and finally outputs the computed path to `ReferenceLineInfo`.

### DecidePathBounds
This function decides the path boundaries (`candidate_path_boundaries`) within which the vehicle drives, by analyzing the ego lane and the vehicle position.

It initializes the path boundary with `PathBoundsDeciderUtil::InitPathBoundary`. The function `GetBoundaryFromSelfLane` updates the path boundary according to the ego lane information, and the function `ExtendBoundaryByADC` extends the path boundary according to the ego vehicle position and speed.

### OptimizePath
This function is used to optimize the path. It takes two parameters: `candidate_path_boundaries` (the path boundaries) and `candidate_path_data` (which stores the candidate path data).

The function computes the path curvature constraints (`ddl_bounds`), the curvature rate (`jerk_bound`), and the reference path (`ref_l` and `weight_ref_l`).
It calls `PathOptimizerUtil::OptimizePath` to optimize the path. If the optimization succeeds, the computed path `PathData` object is added to `candidate_path_data`.

### AssessPath
This function is used to evaluate whether the generated path is feasible. For the path generated by `OptimizePath`, it determines whether it is empty, whether the path deviates from the reference line, and whether the path deviates from the road.

#### Usage
##### Configuring the FallbackPath Task plugin to load
In `modules/planning/scenarios/xxxx/conf/pipeline.pb.txt`, add the corresponding configuration in the scenario xxxx in which you want to add the `FallbackPath` plugin. In the configuration parameters, `name` is the name of the task, which is user-defined and only needs to make clear which task it is, and `type` is the class name of the task, that is, `FallbackPath`.
```
task {
  name: "FALLBACK_PATH"
  type: "FallbackPath"
}
```
##### Configuring FallbackPath parameters
In `modules/planning/tasks/fallback_path/conf/default_conf.pb.txt`, configure the parameters of the `FallbackPath` plugin.
In `modules/planning/planning_component/conf/planning.conf`, configure the gflag parameters that act on the `FallbackPath` plugin.
##### Starting planning
```shell
mainboard -d modules/planning/planning_component/dag/planning.dag
```
