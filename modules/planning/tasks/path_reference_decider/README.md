planning-task-path-reference-decider
==============

## Introduction
`PathReferenceDecider`  This task can make decisions on the reasonableness of the path generated by inference, for use in subsequent solving.


### Process
The following decisions are made according to reference_info

1) If reference_line_info>1, that is, a lane change is in progress, the decision process is skipped, the usage rate of learning_model_output is kept at its current value, errmsg is set to indicate that a lane change is in progress, and status ok is returned

2) During overtaking, the decision process is skipped. The usage rate of learning_model_output is kept at its current value, errmsg is set to indicate that overtaking is in progress, and status ok is returned

3) Determine whether there is a regular boundary. If not, return the error code status errcode. This step uses the GetRegularPathBound method

4) When the inference model has no output, the ordinary rule-based method is used for the path decision, and status ok is returned  

5) Use the AdjustTrajectoryWhichStartsFromCurrentPos method to determine the start point of the plan in the path.
   When the size of the inference model output is too short (<=1), the path output by the model inference is also not used, and status ok is returned

6) Add the points in the inferred trajectory to pathpoints

7) Call the IsValidPathReference method to determine whether it is a valid path reference. If invalid, output an error message and return ok

8) Call EvaluatePathReference to evaluate the inferred path reference

9) Update the validity rate of the inference model and record some logs


### ConvertTrajectoryToPath
Adds the path points in the trajectory to the path points of the path

### GetRegularPathBound
Looks for a pathbound labeled regular: it traverses all passed-in boundaries to determine whether there is a regular bound, and if a regular bound is found, returns the distance from the start of the bound to the current bound.

### IsValidPathReference
Determines whether the path reference is valid, by calling the IsPointWithinPathBounds method to determine whether points in the path reference exceed the path boundary.

### IsADCBoxAlongPathReferenceWithinPathBounds
Unused method

### PathBoundToLineSegments
Unused method

### IsPointWithinPathBounds
Used to determine whether a point is within the path boundary.

### EvaluatePathReference
Evaluates the path reference generated by inference by calling the discrete_path_reference.Evaluate method

### RecordDebugInfo
Records some information related to the pathname and pathpoints

#### Usage
##### Configuring the PathReferenceDecider Task plugin to load
In `modules/planning/scenarios/xxxx/conf/pipeline.pb.txt`, add the corresponding configuration in the scenario xxxx in which you want to add the `PathReferenceDecider` plugin. In the configuration parameters, `name` is the name of the task, which is user-defined and only needs to make clear which task it is, and `type` is the class name of the task, that is, PathReferenceDecider.
```
task {
  name: "PATH_REFERENCE_DECODER"
  type: "PathReferenceDecider"
}

##### Configuring PathReferenceDecider parameters
In `modules/planning/tasks/path_reference_decider/conf/default_conf.pb.txt`, configure the parameters of the `PathReferenceDecider` plugin.
In `modules/planning/planning_component/conf/planning.conf`, configure the gflag parameters that act on the `PathReferenceDecider` plugin
##### Starting planning
```shell
mainboard -d modules/planning/planning_component/dag/planning.dag
```
