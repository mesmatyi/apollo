# Prediction module analysis
## Purpose:
Predict the motion trajectories of obstacles; each trajectory has a probability value.

## Input:
 * Vehicle position information: /apollo/localization/pose ([pb_msgs/LocalizationEstimate]).
 * Obstacle information: /apollo/perception/obstacles ([pb_msgs/PerceptionObstacles]).

## Output:
Motion trajectories of obstacles. /apollo/prediction[pb_msgs/PredictionObstacle].

## Node diagram:
![prediction data flow](images/prediction_node_arch.bmp)

## Submodules:
 * Container: stores the data from the subscribed topics.
 * Evaluator: for any obstacle, the evaluator predicts paths and speed. An evaluator gives a probability value for each path by using the evaluation models under _prediction/data/_.
 * Predictor: the predictor predicts channels for obstacles; the current channels include the following:
   * Lane sequence: the obstacle can only move along lanes.
   * Free movement: the obstacle moves freely.
   * Region movement: the obstacle can only move within a certain region.

## Source code architecture:
 * main.cc: starts the /prediction node.
 * prediction.cc and prediction.h:
	  * Name() function: returns the node name prediction.
	  * Init() function:
        * Uses the configuration file prediction_conf.pb.txt to set prediction_conf_, mainly setting the channel types generated by the predictor.
        * Uses the configuration file adapter.conf to set adapter_conf_, setting the node topic types.
        * Initializes AdapterManager, defining the node handle and topics.
        * Initializes ContainerManager, creating one Container for each subscribed topic to receive the topic data.
        * Initializes EvaluatorManager: registers one Evaluator, MLP_EVALUATOR; configures MLP_EVALUATOR according to prediction_conf.pb.txt, which seems to focus on vehicles on the road, and sets vehicle_on_lane_evaluator_.
        * Initializes PredictorManager: registers four Predictors, and sets vehicle_on_lane_predictor_, vehicle_off_lane_predictor_ and pedestrian_predictor_.
        * Checks whether the localization and perception nodes are ready.
        * Sets the callback functions OnLocalization and OnPerception for localization and perception data.
	  * OnLocalization function:
        * Gets the obstacle container obstacles_container.
        * Gets the position pose_container.
        * Stores the newly arrived position message into pose_container.
        * Updates the obstacle information.
	  * OnPerception function:
        * Gets the obstacle container obstacles_container.
        * Stores the newly arrived obstacle information into obstacles_container.
        * Runs the Evaluator.
        * Runs the Predictor.
        * Updates the header structure of the prediction_obstacles to be published, and publishes the message.

## Evaluator:
 * Creating a new NewEvaluator:
   * data/mlp_vehicle_model.bin: the core part of the evaluator, implemented with deep learning.
   * The configured output of the feature.proto or lane_graph.proto files; their purpose is unclear.
   * Under the evaluator/vehicle/ directory, implement a new evaluator class NewEvaluator with Evaluator as the base class, referring to the mlp_evaluator implementation.
   * Specify the new evaluator class in the prediction_conf.pb.txt file.
   * Modify the default evaluator class in evaluator_manager.h.
 * The Run() function in evaluator_manager.cc:
   * Gets the obstacle container container.
   * Iterates over all obstacles, and uses the obstacle id and the obstacle container to get the obstacle information obstacle.
   * For obstacles on a lane, calls Evaluate to evaluate them.
 * The Evaluate() function in mlp_evaluator.cc:
   * Takes a single obstacle as its parameter. Computes the features of the single obstacle and computes its probability.
   * Each obstacle_ptr contains multiple lane_graph_ptr.
   * feature_values can be computed using obstacle_ptr and lane_graph_ptr.
   * The probability value probability is computed from feature_values.
   * The probability value probability is set on lane_sequence_ptr.
   * Further analysis requires understanding the concepts of feature and lane_sequence and going into the algorithms; for now the evaluator analysis stops here.

## Predictor:
 * Function: predict the future trajectories of obstacles.
 * Creating a new predictor NewPredictor:
   * Create a new directory vehicle under predictor/.
   * Create new_predictor.h and new_predictor.cc under the vehicle directory, mainly defining and implementing the subclass NewPredictor inheriting from the Predictor class. For the concrete implementation, refer to sibling directories of vehicle such as free_move.
   * Update the configuration file prediction_conf.pb.txt to add the new predictor type.
   * Update the manager: modify the default predictor type in the file predictor_manager.h.
 * The run() function in prediction_manager.cc:
   * Gets the obstacle container container.
   * Sets the timestamp of the predicted obstacles.
   * Gets the obstacle information obstacle according to the id in the predicted obstacle and the container.
   * Sets the predictor type predictor according to the type in the predicted obstacle.
   * Passes in the obstacle information and executes predictor->Predict(obstacle).
   * Configures all trajectories of the obstacle into the predicted obstacle, and updates the timestamp.
 * The predictor function Predict():
   * Gets the feature from the obstacle information.
   * Gets num_lane_sequence from the feature.
   * Iterates over num_lane_sequence and gets the sequence through the feature.
   * Gets curr_lane_id from the sequence.
   * Gets TrajectoryPoint from curr_lane_id through the DrawLaneSequenceTrajectoryPoints() function.
   * Gets the trajectory from TrajectoryPoint through the GenerateTrajectory() function.
   * Sets the probability of this trajectory and stores it into the trajectories_ vector.
   * Similar to the Evaluator, further analysis requires understanding the specific algorithms; for now it stops here.
