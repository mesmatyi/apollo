### Problem Description:

After normal compilation and use, the power was cut off immediately and forcibly. As a result, after restarting, errors appear when compiling again and when running modules:
* Recompiling shows a metadata parsing error and then exits:
![](images/metadata_error.png)

* Running a module shows that the dynamic library cannot be found:
![](images/loading_error.png)

### Cause:
For data written to disk, the Linux kernel first stages it in a cache and writes it to disk later. Cutting power immediately means the kernel did not have time to write the compilation outputs in the cache to the output path, which causes problems in subsequent compilation and running.
It is recommended not to power off the domain controller directly and forcibly. Instead, enter
shutdown
on the command line and then power off, which ensures the data in the cache is written to disk.

### Solution:
#### If you are using package management:
1. For compilation errors, use the latest version of buildtool, which automatically handles these missing-file errors:
```shell
buildtool upgrade && buildtool build
```

2. For module runtime errors, recompile so that buildtool automatically installs the missing dependencies, then manually delete the ld cache and run the script to regenerate it, and then run the module again:
```shell
sudo rm -f /etc/ld.so.conf.d/apollo.conf && sudo bash /opt/apollo/neo/update_dylib.sh
```

#### If you are using source code:
1. Recompile Apollo:
```bash
bash apollo.sh build_opt_gpu
```
