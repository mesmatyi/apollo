## Step 1: Record a Trajectory

### 1. Start the Canbus Driver

After starting the industrial PC (IPC), open a command-line terminal (Terminal) on the desktop, go to the CAN card directory (by default under the home path), and start the CAN driver:

```bash
bash ~/socketcan/start.sh
```

### 2. Start the Apollo Docker Environment

### If you are using package management, follow these steps:

#### Open a command-line terminal and change the path to Apollo:

```bash
cd ~/apollo
```

#### Enter the following commands to enter the Apollo Docker environment:

```bash
aem start #Create the container
aem enter #Enter the container
buildtool build
```

> Note: When entering the container for the first time, use `buildtool build`; if you only want to build the updated modules, use the following command: `buildtool build -p module_name`.

If your terminal looks like the one below, you have successfully entered the Apollo runtime container:

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_7e7a575.png)

### If you are using the source code, follow these steps to enter the docker environment:

#### Open a command-line terminal and change the path to Apollo:

```bash
cd ~/apollo     #Change the path to apollo; note there is a space between cd and ~/apollo
```

#### Enter the following command to start the Apollo Docker environment:

```bash
bash docker/scripts/dev_start.sh
```

Enter the docker environment:

```bash
bash docker/scripts/dev_into.sh
```

If your terminal looks like the one below, you have successfully entered the Apollo runtime container:

```bash
[user@in-runtime-docker:/apollo]$
```

### 3. Start and Open Dreamview+

You can start Dreamview+ through package management or from source. Choose one method and start Dreamview+ with the corresponding commands.

#### Start Dreamview+

##### Method 1: Package Management

After entering the docker environment through package management, run the following command in the docker environment to start Dreamview+:

```bash
aem bootstrap start --plus
```

> Note:
>
> - If you want to stop Dreamview+, enter `aem bootstrap stop --plus`.
> - If you want to restart Dreamview+, enter `aem bootstrap restart --plus`.

##### Method 2: Source Code

After entering the docker environment from source, run the following command in the docker environment to start Dreamview+:

```bash
bash scripts/bootstrap.sh start_plus
```

> Note:
>
> - If you want to stop Dreamview+, enter `bash scripts/bootstrap.sh stop_plus`.
> - If you want to restart Dreamview+, enter `bash scripts/bootstrap.sh restart_plus`.

#### Open Dreamview+

After a successful start, enter the URL `localhost8888` in the browser to open the Dreamview+ interface.

## Step 2: Record the Trajectory

### 1. Select the Record-and-Replay Mode

In **Mode**, select the **Vehicle Test** mode.

In **Operations**, select the **Waypoint_Follow** operation (record-and-replay).

### 2. Select the Vehicle

- If there is a corresponding vehicle configuration, you can select it.

- If there is no corresponding vehicle configuration, you can use the default configuration.

### 3. Start the Modules Related to Record-and-Replay Driving

In **Modules**, start the **Canbus**, **Control**, **ExternalCmd**, **GPS**, **Lidar**, **Localization**, **Prediction**, **Radar** and **Transform** buttons.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_6e892d2.png)

> Note: ExternalCmd is a subprocess of planning and is used by record-and-replay. In road test mode, you only need to enable the planning module.

### 4. Check the Connection Status

Check the Component status.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_d8ce70a.png)

> Notes:
>
> - A green OK in Component means normal, and you can proceed with the following operations.
> - A yellow WARNING only means the signal is poor; the module has already started. As long as it is not ERROR, it does not affect record-and-replay.

Start cyber_monitor to view the channel information.

Check the cyber_monitor data.

Enter the docker environment and type `cyber_monitor`. In the cyber_monitor tool that starts, you can see many channels. Among them, /tf and /tf_static correspond to the Transform module, /apollo/localization/pose corresponds to the Localization module, and apollo/sensor/gnss/best_pose corresponds to the GPS module.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_4650e42.png)

Use the up and down arrow keys to select the channel /apollo/sensor/gnss/best_pose and press the right arrow key to enter it. Check whether the sol_type item is NARROW_INT. If it is NARROW_INT, the GPS signal is good and meets the localization requirements; if it is not NARROW_INT, move the vehicle with the remote controller until NARROW_INT appears.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_f716d6d.png)

After confirming that all enabled modules are working normally, you can proceed with the following operations.

### 5. Start Trajectory Recording

Drive the vehicle by remote control to the start of the trajectory to be recorded, and mark the vehicle's heading and position at this point. You can draw a cross at the vehicle's front left wheel as a marker, as shown below:

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_3baaba6.png)

Click the **Record** button in the bottom operation bar to start trajectory recording.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_7a6ea57.png)

### 6. Stop Trajectory Recording

Use the remote controller to drive the vehicle along a trajectory. A straight line is recommended here. After the vehicle stops, click the **Stop** recording button to end the record-and-replay recording.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_7d4538e.png)

After stopping the trajectory recording, enter a name for the data package in **Record Name** and click **Save**.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_06fcbdf.png)

> Note: There are restrictions on the naming rules for data packages.

## Step 3: Start the Record-and-Replay Driving Demo

### 1. Drive the vehicle by remote control to the start position used when recording the record-and-replay data in the previous section.

At this point, a blue trajectory line is generated in front of the vehicle in Dreamview+. This trajectory line is the one generated by the record-and-replay recording just made. Check that the generated trajectory line is clear and free of burrs, and confirm that the trajectory roughly matches the actual route. If there is a large difference (for example, you recorded a straight drive but the trajectory shows a sharp turn), re-check the localization and record a new trajectory line.

> Note: The start position and heading of the vehicle should be kept as consistent as possible with the start position and heading used when recording.

### 2. Switch the remote controller to autonomous driving mode.

### 3. In Dreamview+, click the **START** button in the bottom operation bar to start autonomous driving.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_dce1d0f.png)

The vehicle starts record-and-replay and drives autonomously along the existing trajectory. Observe the vehicle's motion, including whether its speed and direction are consistent with the earlier recording.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_bcb38a2.png)

> Note:
>
> - During record-and-replay autonomous driving, the perception-related sensors are not used, and the vehicle will neither brake nor avoid when it encounters obstacles. In an emergency, take over promptly with the remote controller. This is also why you should look for a spacious, enclosed site with few people and vehicles.
> - The vehicle may start off rather abruptly. Be ready to take over with the remote controller at any time, and in an emergency press the emergency stop button quickly.

### 4. After the vehicle finishes record-and-replay, take over promptly with the remote controller.
