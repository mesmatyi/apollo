## Step 1: Prepare for Autonomous Driving

### 1. Start the CAN Card

After starting the industrial PC (IPC), open a command-line terminal (Terminal) on the desktop, go to the CAN card directory (by default under the home path), and start the CAN driver:

```bash
bash ~/socketcan/start.sh
```

## Step 2: Start and Open Dreamview+

### 1. Start the Apollo Docker Environment

#### If you are using package management, follow these steps:

##### Open a command-line terminal and change the path to Apollo:

```bash
cd ~/apollo
```

##### Enter the following commands to enter the Apollo Docker environment:

```bash
aem start #Create the container
aem enter #Enter the container
buildtool build
```

> When entering the container for the first time, run build.
> If you only want to build the updated modules, use the following command: `buildtool build -p module_name`.

     If your terminal looks like the one below, you have successfully entered the Apollo runtime container:

     ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_af1a780.png)

#### If you are using the source code, follow these steps to enter the docker environment:

##### Open a command-line terminal and change the path to Apollo:

```bash
cd ~/apollo     #Change the path to apollo; note there is a space between cd and ~/apollo
```

##### Enter the following command to start the Apollo Docker environment:

```bash
bash docker/scripts/dev_start.sh
```

Enter the docker environment:

```bash
bash docker/scripts/dev_into.sh
```

If your terminal looks like the one below, you have successfully entered the Apollo runtime container:

```bash
[user@in-runtime-docker:/apollo]$
```

### 2. Start Dreamview+

#### In the Apollo Docker environment, start the Dreamview+ interface:

##### If you are using package management, run the following command in the docker environment to start Dreamview+:

```bash
aem bootstrap start --plus
```

> Note:
>
> - If you want to stop Dreamview+ (for example, when you get the message `Fail to start Dreamview`), enter `aem bootstrap stop --plus`.
> - If you want to restart Dreamview+, enter `aem bootstrap restart --plus`.

##### If you are using the source code, run the following command in the docker environment to start Dreamview+:

```bash
bash scripts/bootstrap.sh start_plus
```

> Note:
>
> - If you want to stop Dreamview+, enter `bash scripts/bootstrap.sh stop_plus`.
> - If you want to restart Dreamview+, enter `bash scripts/bootstrap.sh restart_plus`.

#### Open Dreamview+.

After a successful start, enter the URL `localhost8888` in the browser to open the Dreamview+ interface.

### 3. Select the Mode and Operation

In **Mode**, select **Vehicle Test**.

In **Operations**, select **Auto Drive**.

### 4. Select the Vehicle and Map

In **ADS Resources**, select the vehicle for the real-vehicle road test mode.

- If there is a corresponding vehicle configuration, you can select it.

- If there is no corresponding vehicle configuration, you can use the default configuration.

In **Environment Resources** > **HD Map**, select the map required for the real-vehicle road test mode.

### 5. Enable the Required Modules

Start the required **Canbus**, **Control**, **ExternalCmd**, **GPS**, **Lidar**, **Localization**, **Planning**, **Prediction**, **Radar** and **Transform** modules.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_62fa920.png)

ExternalCmd is a submodule of the Planning module and is used by record-and-replay. In real-vehicle mode, you only need to enable the Planning module.

### 6. Check the Connection Status

Check the Component status.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_30928e6.png)

> Notes:
>
> - A green OK in Component means normal, and you can proceed with the following operations.
> - A yellow WARNING only means the signal is poor; the module has already started. As long as it is not ERROR, it does not affect operation.

Check the cyber_monitor data.

Enter the docker environment and type `cyber_monitor`. In the cyber_monitor tool that starts, you can see many channels. Among them, /tf and /tf_static correspond to the Transform module, /apollo/localization/pose corresponds to the Localization module, and apollo/sensor/gnss/best_pose corresponds to the GPS module.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_4650e42.png)

Use the up and down arrow keys to select the channel /apollo/sensor/gnss/best_pose and press the right arrow key to enter it. Check whether the sol_type item is NARROW_INT. If it is NARROW_INT, the GPS signal is good and meets the localization requirements; if it is not NARROW_INT, move the vehicle with the remote controller until NARROW_INT appears.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_f716d6d.png)

After confirming that all enabled modules are working normally, you can proceed with the following operations.

### 7. Edit the Driving Route

In the **Vehicle Visualization** panel, click the **Routing Editing** button to enter the route editing feature.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_17803eb.png)

Click the start position icon at the upper left of the panel, then click on the map to set the start position.

> Note: Press and hold the right mouse button to drag and move the map.

Click the trajectory point icon at the upper left, then click on the map to add waypoints.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_b951b5a.png)

Click **Save Editing** to finish drawing the trajectory.

Click the **Routing** button and a red trajectory line appears.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_ae5fcdc.png)

## Step 2: Start Autonomous Driving

If all modules are working properly and the planning results are good, switch the remote controller to the autonomous driving state.

In Dreamview+, click the **START** button in the bottom operation bar to start autonomous driving.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_053c458.png)

> After autonomous driving starts, the green trajectory generated is the planned path.
