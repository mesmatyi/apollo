## Overview

Map collection means that, after the tool is deployed on the vehicle, as the vehicle moves along the road, the sensors collect information about the surrounding environment and roads to generate a point cloud base map. The collected raw map data includes RTK and LiDAR data. The map collection tool depends on the LiDAR driver and GNSS localization, so please prepare them in advance.

## Procedure

### Step 1: Environment Check

1. Go to the Dreamview+ interface, select the map collection mode **Map Collect**, and click **Enter this mode** to enter map collection mode.
   
   > Note: Map collection only allows access from a single browser page. The Chrome browser is recommended.

2. Enable the GPS module, Lidar module, localization module and Transform module, and wait until the status of the GPS module, Lidar module and localization module is shown as normal (green).

3. Select the collection algorithm. Two are currently provided: a regular algorithm based on RTK localization point cloud fusion, and a SLAM algorithm based on SLAM localization point cloud fusion. This section uses the **regular algorithm** as an example.
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_0b09997.png)

### Step 2: Data Collection

1. Click the **Start Collection** button.

2. Move the vehicle along the route to be collected.
   
   > Note: Depending on your LiDAR configuration, a LiDAR with 32 or more lines usually needs to travel each road twice (one round trip), while a 16-line LiDAR is recommended to travel each road 2 to 3 times. You can first drive a short distance to generate a base map and take a look, then judge from the result whether to adjust the parameters and how many passes are needed.

3. After driving the collection route, click the **End Collection** button.
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_3c5bbf5.png)
   
   > Note: In SLAM mode, loop closure detection is needed to calibrate the position information, which takes some time to compute.

4. After collection ends, the system automatically generates the base map.
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_b970989.png)

### Step 3: File Export

After the base map is generated, the system automatically previews it and saves it to the default folder.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_7a529f0.png)

## Offline Base Map Generation Tool

To avoid having to re-collect data when an exception occurs during base map generation, we provide an offline base map generation tool.

First edit the base map generation configuration:

```bash
vim /apollo/modules/private_tools/tile_map_images_creator/conf/image_creator_conf.pb.txt
```

Modify the `input_output_conf` configuration. Taking a collection directory of `data/records/map_record_20240401103023` as an example, change it to:

```bash
input_output_conf {
    input_dir: "/apollo_workspace/data/records/map_record_20240401103023"
    bin_output_dir: "/apollo/data/base_map/20240401103023/map_bin"
    images_output_dir: "/apollo/data/base_map/20240401103023/map_images"
    use_LRU_cache: true
    LRU_cache_size: 20
}
```

Before running the offline base map generation tool, the transform module needs to be started. Please enable the transform module in the Dreamview page in advance, or run it manually:

```bash
mainboard  -d /apollo/modules/transform/dag/static_transform.dag &
```

Then run the offline base map generation tool:

```bash
tile_map_images_creator -c /apollo/modules/private_tools/tile_map_images_creator/conf/image_creator_conf.pb.txt
```

The base map is generated under the `/apollo/data/base_map/20240401103023` directory, and you can open map editing mode to preview it.
