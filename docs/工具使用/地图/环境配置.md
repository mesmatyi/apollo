First contact the Apollo team to add map tool permissions to your Apollo account.

## Step 1: Environment Deployment

The map tool can run on both x86_64 and aarch64 architectures. Deployment:

```bash
# Download the Apollo development project
git clone https://github.com/ApolloAuto/application-core
# Enter the project directory
cd application-core/
# Pull the latest configuration
git pull
# Environment configuration: detects whether the host system is x86_64 or aarch64 and modifies the corresponding .env and .workspace.json configuration
bash setup.sh
# Start the container
aem start_gpu
# Enter the container
aem enter
# Install
buildtool build

# The profiles directory in application-core provides a sample configuration based on one 16-line LiDAR and 2 cameras. You can copy the sample directory and modify the configuration in it according to your vehicle model
# Select your profile; taking the sample profile as an example:
aem profile use sample
# Note: the profile use command may print some warnings, which can usually be ignored.
```

## Step 2: Configuration Files

### Mode Configuration Files

The mode configuration files include the map collection mode configuration and the map editing mode configuration files.

#### Map Collection Mode Configuration File

Path: `/apollo/modules/dreamview_plus/conf/hmi_modes/map_collect.pb.txt`.

> Note: It mainly contains the configuration for starting the lidar, gps, localization and transform modules. The default configuration can usually be used. If you need to modify it, make sure the dag and conf configuration file paths are correct.

#### Map Editing Mode Configuration File

Path: `/apollo/modules/dreamview_plus/conf/hmi_modes/map_editor.pb.txt`.

> Note: The configuration in it does not need to be changed.

### Parameter Configuration

#### Map Collection Parameter Configuration

Path: `/apollo/modules/private_tools/tile_map_images_creator/conf/image_creator_conf.pb.txt`.

> Note: The configurations marked in red below are the ones you need to modify or pay attention to; the default values can usually be used for the others.
> 
> * reader_conf:
>   * point_cloud_channel: the point cloud channel used to draw the base map; usually the name of the compensator point cloud channel,
> * point_cloud_processing_conf:
>   * intensity_converter_conf (pay special attention to this configuration item): the configuration of the sigmoid converter. It contains k and x0; usually you only need to pay attention to x0. Increasing x0 generally makes the base map darker, and decreasing it makes it brighter. According to some current test results, setting x0 to 11.0~15.0 works better on darker painted road surfaces, and setting x0 to 18.0~20.0 usually works better on lighter-colored concrete road surfaces. You can start with the default value.
>   * filter_conf: the point cloud filtering conditions, including the filtered point cloud height and point cloud range; usually no modification is needed.
> * matrix_generator_conf. It contains the precision and the maximum level of the initially generated tiles. The precision is the physical distance covered by each pixel of each image of the tiles at the maximum level; usually no modification is needed. The map is usually divided into five levels, 0~4, and the resolution of each tile is 1024\*1024. The physical distance of each pixel of a level-4 tile is the precision, that is, 0.03125\*0.3125 m^2, and each level-4 tile represents a physical range of 32\*32 m^2. The length and width of the physical range represented by each upper-level tile are each twice those of the level below; for example, level 3 represents a 64\*64 physical range, level 2 represents a 128\*128 range, and so on.
> * sample_distance: the purpose is to filter out point cloud frames that are too close, limiting the minimum distance interval between two point cloud frames used. If all point clouds need to be used for rendering, set it to 0.0.

#### Map Editing Quality Inspection Parameter Configuration

Paths:

* Inspection item configuration file: `/apollo/modules/private_tools/map_tool/conf/map_validator_checker_conf.pb.txt`
* Inspection level configuration file: `modules/private_tools/map_tool/conf/map_validator_errcode_conf.pb.txt`

> Notes:
> 
> * Inspection item configuration: usually no modification is needed. It includes lane width checks, curvature checks, whether drawn elements are associated with lanes, parking space size checks, and so on;
> * Inspection level configuration: items of type Error block map publishing, while Warning only raises a warning and does not block map publishing.

#### SLAM Mapping Related Configuration

If you use slam mode for mapping, you need to pay attention to the following configurations.

**laser_multiscan_registration_conf**

Path: `/apollo/modules/loam_velodyne/conf/laser_multiscan_registration_conf.pb.txt`

> Note: Mainly modify the channel configuration and the imu configuration.
> 
> * pointCloudTopic: change it to the point cloud channel used for slam mapping (note that it must be the raw lidar point cloud; do not use a fused or motion-compensated point cloud),
> * IMU Settings: includes settings such as IMU type (6-axis or 9-axis), IMU frequency, IMU noise and bias. The default provided is the configuration information of the Xingyu Wangda M2.

**laser_odometry_conf**

Path: `/apollo/modules/loam_velodyne/conf/laser_odometry_conf.pb.txt`

> Note: Mainly modify the channel configuration.
> 
> * pointCloudTopic: consistent with the point cloud channel above,
> * lidarFrame: consistent with the frame id output by the lidar,
> * Sensor Settings: configuration of the LiDAR parameters, including the LiDAR type (velodyne can generally be set), the number of LiDAR beams, the horizontal resolution, and so on.

**localization_conf**

Path: `/apollo/modules/loam_velodyne/conf/localization_conf.pb.txt`

> Note: RTK parameter configuration.
> 
> * pointCloudTopic: consistent with the point cloud channel above,
> * GPS Settings: the threshold of the RTK covariance; usually no modification is needed,
> * CPU Params, Surrounding map, Loop closure and so on are some mapping configurations; usually no modification is needed.

## Step 3: Start the Service

1. In the docker environment, enter the following command to start Dreamview+:
   
   ```bash
   aem bootstrap restart --plus
   ```
   
   In the browser, open the Dreamview+ page by accessing port 8888 of the machine.

2. Login information at the lower left of the page indicates a successful login.
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_5341e20.png)

3. In the mode selection, select **Map Collect** to complete base map collection. See the map collection documentation.

4. In the mode selection, select **Map Editor** to complete map editing. See the map editing documentation.

## Step 4: Result Directories

The results are all saved under the data directory of the project:

* record data: each collection saves the record data in a folder starting with `map_record` under the data/records directory.
* Base map: `data/base_map`, which can be copied directly to other machines for use.
* Map: `data/map_data`, which can be copied directly to other machines for use.
* Editing map: `data/editor_map`, which can be copied directly to other machines for use.
