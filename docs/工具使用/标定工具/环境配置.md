
For a product trial, first contact the Apollo team to add calibration tool permissions to your Apollo account, and then you can use it by opening Dreamview+.

For production use, please contact the Apollo team to sign a purchase contract. After applying for activation on the official website and being approved, add devices and bind product lines, then complete authentication on the vehicle to use it in Dreamview+.

## Step 1: Environment Deployment

The calibration tool can run on both x86_64 and aarch64 architectures. Deployment:

```bash
# Download the Apollo development project
git clone https://github.com/ApolloAuto/application-core
# Enter the project directory
cd application-core/
# Pull the latest configuration
git pull
# Environment configuration: detects whether the host system is x86_64 or aarch64 and modifies the corresponding .env and .workspace.json configuration
bash setup.sh
# Start the container
aem start_gpu
# Enter the container
aem enter
# Install
buildtool build

# The profiles directory in application-core provides a sample configuration based on one 16-line lidar and 2 cameras. You can copy the sample directory and modify the configuration in it according to your vehicle model
# Select your profile; taking the sample profile as an example:
aem profile use sample
# Note: the profile use command may print some warnings, which can usually be ignored.
```

## Step 2: Configuration Files

### Configuration File Description

Path: `/apollo/modules/dreamview_plus_plugins/calibration_tool/conf/calibration_tool.pb.txt`

```bash
lidar_calib { # lidar calibration configuration
    collect_strategy { # calibration data collection strategy
        angle: 0.2 # if the angle difference between the localization info and the previous frame exceeds this threshold, it is recorded as a valid frame. Value: degrees/180°*π
        distance:2.0 # if the distance difference between the localization info and the previous frame exceeds this threshold, it is recorded as a valid frame. angle and distance are in an OR relationship: a frame is recorded if either is met
        total: 200 # number of frames collected
    }
    use_odometry: true # pose information source. true (default): /apollo/sensor/gnss/odometry, false: /apollo/localization/pose
    calibration_data_path: "/apollo/data/calibration/lidar_calibration"  # each calibration creates a {calibration_data_path}/{task_id} directory containing the collection data (collection_data) and calibration result (result) directories
    imu_frame_id: "imu"
    lidar_list [ # lidar list
        {
            name: "lidar16_back" # lidar name, used for frontend display
            lidar_frame_id: "lidar16_back"
            lidar_channel: "/apollo/sensor/lidar16/back/PointCloud2" # name of the channel output by the lidar driver
            extrinsics { # rotation and translation of the initial extrinsics
                qw: 0.707
                qx: 0.0
                qy: 0.0
                qz: 0.707
                tx: 0.0
                ty: 0.0
                tz: 1.49
            }
            output_filename: "/apollo/modules/perception/data/params/lidar16_back_extrinsics.yaml" # calibration result file path (the file must exist and have write permission)
        }
    ]
    calib_height: false # whether to calibrate height, true for yes, false for no
}

camera_calib { # camera calibration configuration
    calibration_data_path: "/apollo/data/calibration/camera_calibration"  ## each calibration creates a {calibration_data_path}/{task_id} directory containing the collection data (collection_data) and calibration result (result) directories
    camera_list [ # camera list
        {
            name: "camera_front_12mm" # camera name, used for frontend display
            camera_channel: "/apollo/sensor/camera/front_12mm/image" # name of the channel output by the camera driver
            camera_frame_id: "camera_front_12mm"
            lidar_channel: "/apollo/sensor/lidar16/back/PointCloud2" # name of the channel output by the lidar driver
            lidar_frame_id: "lidar16_back"
            lidar_rotation: 0 # rotation angle of the lidar point cloud, default is 0 degrees, counterclockwise is positive
            intrinsics_filename: "/apollo/modules/perception/data/params/camera_front_12mm_intrinsics.yaml" # intrinsics file path
            output_filename: "/apollo/modules/perception/data/params/camera_front_12mm_extrinsics.yaml" # calibration result file path (the file must exist and have write permission)
            lidar_to_imu_extrinsic_file_path: "/apollo/modules/perception/data/params/lidar16_back_imu_extrinsics.yaml" # lidar-imu extrinsics path
        },
        {
            name: "camera_front_6mm" # camera name, used for frontend display
            camera_channel: "/apollo/sensor/camera/front_6mm/image" # name of the channel output by the camera driver
            camera_frame_id: "camera_front_6mm"
            lidar_channel: "/apollo/sensor/lidar16/back/PointCloud2" # name of the channel output by the lidar driver
            lidar_frame_id: "lidar16_back"
            lidar_rotation: 0 # rotation angle of the lidar point cloud, default is 0 degrees, counterclockwise is positive
            intrinsics_filename: "/apollo/modules/perception/data/params/camera_front_6mm_intrinsics.yaml" # intrinsics file path
            output_filename: "/apollo/modules/perception/data/params/camera_front_6mm_extrinsics.yaml" # calibration result file path (the file must exist and have write permission)
            lidar_to_imu_extrinsic_file_path: "/apollo/modules/perception/data/params/lidar16_back_imu_extrinsics.yaml" # lidar-imu extrinsics path
        }
    ]
}
```

`pre_rotation angle` setting: in the Apollo framework, this value is set as shown in the figure below. Its meaning is to rotate the camera clockwise by this angle so that its orientation is consistent with the orientation of the LiDAR:

## Step 3: Start the Service

1. In the docker environment, enter the following command to start Dreamview+:

   ```bash
   aem bootstrap restart --plus
   ```

   In the browser, open the Dreamview+ page by accessing port 8888 of the machine.

2. Login information at the lower left of the page indicates a successful login.

   ![3.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Studio/3_5341e20.png)

3. In the mode selection, select **Lidar Calibration** to start lidar calibration. See the [lidar calibration](./激光雷达标定.md) documentation.
4. In the mode selection, select **Camera Calibration** to start camera calibration. See the [camera calibration](./相机标定.md) documentation.

## Step 4: Result Directories

The results are all saved under the `data/calibration` directory of the project.

### Lidar Calibration Results

Generally in the `data/calibration/lidar_calibration` directory, with each lidar calibration run recorded under a timestamp-named directory, such as lidar2imu_171232645, where:
* the collection_data directory saves the collected point clouds and position information,
* the result directory saves the calibration results: find the directory of the corresponding lidar; result.pcd is the fused pcd from calibration, and result.yaml records the calibrated extrinsic values.
### Camera Calibration Results

Generally in the `data/calibration/camera_calibration` directory, with each camera calibration run named by time, such as camera2lidar_20240405220953, where:
* the files named starting with the configured camera name save the original camera image and lidar point cloud pairs, and the result directory saves the result corresponding to each collection,
* the failed_data directory stores the image and point cloud pairs whose collection failed,
* extrinsic.yaml stores the final extrinsic information.
