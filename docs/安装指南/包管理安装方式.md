# Installing via Package Management

## Step 1: Install the Base Software

### 1. Install Ubuntu Linux

For the steps to install Ubuntu 18.04+, see the [official installation guide](https://ubuntu.com/tutorials/install-ubuntu-desktop).

After the installation, update the related software:

```shell
sudo apt-get update
sudo apt-get upgrade
```

> Note: A network connection is required to complete the update.

### 2. Install Docker Engine

Apollo depends on Docker 19.03+. To install Docker Engine, you can follow the official documentation:

- See [Install Docker Engine on Ubuntu](https://docs.docker.com/engine/install/ubuntu/).

- You can also install it directly with the installation script provided by Apollo:

```shell
wget http://apollo-pkg-beta.bj.bcebos.com/docker_install.sh
bash docker_install.sh
```

The script may need to be run several times during this process; just follow the script prompts.

## Step 2 (Optional): Get GPU Support

Some Apollo modules (for example, the perception module) require GPU support to compile and run. If you need to use such modules, you need to install the Nvidia graphics driver and the Nvidia
container toolkit to get GPU support.

> Note: This tutorial applies only to Ubuntu. Graphics drivers cannot be installed in virtual machines; for WSL, please search online.
> Note: If you have already installed the Nvidia graphics driver, that is, entering `nvidia-smi` in the terminal produces normal output, you can skip the section `1. Install the Driver`.

### 2. Install the Nvidia container toolkit

To get GPU support inside containers, you need to install the NVIDIA Container Toolkit after installing Docker. Run the following commands to install the NVIDIA Container
Toolkit:

```shell
distribution=$(. /etc/os-release;echo $ID$VERSION_ID)
curl -s -L https://nvidia.github.io/nvidia-docker/gpgkey | sudo apt-key add -
curl -s -L https://nvidia.github.io/nvidia-docker/$distribution/nvidia-docker.list | sudo tee /etc/apt/sources.list.d/nvidia-docker.list
sudo apt-get -y update
sudo apt-get install -y nvidia-docker2
```

After the installation is complete, you need to restart Docker manually:

```shell
sudo systemctl restart docker
```

## Step 3: Install the Apollo Environment Manager

The Apollo environment manager (aem) is a command-line tool that helps manage and start Apollo environment containers.

### 1. Install Dependencies

```shell
sudo apt-get update
sudo apt-get install ca-certificates curl gnupg
```

### 2. Add the Apollo Package Source's gpg Key on the Host, and Set Up the Source and Update

```shell
# Add the gpg key
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://apollo-pkg-beta.cdn.bcebos.com/neo/beta/key/deb.gpg.key | sudo gpg --dearmor -o /etc/apt/keyrings/apolloauto.gpg
sudo chmod a+r /etc/apt/keyrings/apolloauto.gpg

# Set up the source and update
echo \
    "deb [arch="$(dpkg --print-architecture)" signed-by=/etc/apt/keyrings/apolloauto.gpg] https://apollo-pkg-beta.cdn.bcebos.com/apollo/core"\
    $(. /etc/os-release && echo "$VERSION_CODENAME") "main" | \
    sudo tee /etc/apt/sources.list.d/apolloauto.list
sudo apt-get update
```

> Note: If you have previously installed Apollo 8.0, the `/etc/apt/sources.list` file on the host will contain a line like
> `deb https://apollo-pkg-beta.cdn.bcebos.com/neo/beta bionic main`, which can be deleted directly. The Apollo source configuration on the host is only used to install
> the `aem` tool.

### 3. Install aem:

```shell
sudo apt install apollo-neo-env-manager-dev --reinstall
```

After a successful installation, you can use it:

```shell
aem -h
```

## Step 4: Install a Sample Project

### 1. Choose a Sample Project

Apollo currently provides 3 sample projects. You can choose one according to your needs.

- [application-core](https://github.com/ApolloAuto/application-core), contains all Apollo open-source packages; you can build your own application based on this project

- [application-pnc](https://github.com/ApolloAuto/application-pnc), contains only planning and control related packages, suitable for users who focus only on planning and control

- [application-perception](https://github.com/ApolloAuto/application-perception), contains only perception related packages, suitable for users who focus only on perception

### 2. Clone the Project

Take the x86 application-core as an example:

```shell
git clone https://github.com/ApolloAuto/application-core.git application-core
```

### 3. Start the Apollo Environment Container

```shell
# First enter the project directory
cd application-core
# Environment setup: detect whether the host is x86_64 or aarch64, and modify the corresponding .env and .workspace.json configuration
bash setup.sh
# Start the container
aem start
```

### 4. Enter the Apollo Environment Container

```shell
# First enter the project directory
cd application-core
# Enter the container
aem enter
```

### 5. Install Software Packages

The sample project contains a directory named `core`. The `core/cyberfile.xml` file describes the packages the project depends on, and the dependency packages can be installed with the buildtool tool:

```shell
buildtool build -p core
```

> What this operation actually does is build the package `core` in the project, but `core` itself has no code to compile, so this operation only installs the dependency packages declared in `core/cyberfile.xml`.

### 6. Select a Vehicle Configuration

The profiles/sample directory in the sample project is an officially provided vehicle configuration based on one LiDAR and two cameras. You can refer to the sample under the profiles directory to write your own vehicle configuration. To activate a vehicle configuration:

```shell
# Take sample as an example
aem profile use sample
```

### 7. Play a Data Package

#### Get the Data Package

```shell
wget https://apollo-system.cdn.bcebos.com/dataset/6.0_edu/demo_3.5.record -P $HOME/.apollo/resources/records/
```

#### Get the Map Corresponding to the Data Package

```shell
buildtool map get sunnyvale
```

> Starting from version `9.0.0-rc-r10`, map data has been separated out and must be downloaded separately; it is no longer released with the map package. You can view all available maps with `buildtool map list`.

#### Start Dreamview+

```shell
aem bootstrap start --plus
```

##### Play a Data Package in Dreamview+

After starting Dreamview+, enter `localhost:8888` in your browser to open the Dreamview+ interface. You can choose the default mode or another mode to play data packages. This section takes the default mode as an example.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_alpha_doc/image_7deb2d2.png)

1. Select **Default Mode**.

2. Check **Accept the User Agreement and Privacy Policy**, and click **Enter this Mode** to go to the **Mode Settings** page.

3. On the **Mode Settings** page, set the playback parameters.
   
   - In **Operations**, select **Record**.
   - In **Environment Resources**, click **Records** and select the data package you want to play.
   - In **Environment Resources**, click **HDMap** and select **Sunnyvale Big Loop**.

4. Click the play button in the bottom area.
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Doc_CN_9_0/image_45acc2d.png)
   
   You can see the data package playback in **Vehicle Visualization**.

##### Play a Data Package from the Command Line

1. Enter the docker environment.

2. In Dreamview+, under **Resource Manager** > **Records**, first download the required data package. Enter the following command to play the data package:
   
   ```bash
   cyber_recorder play -f ~/.apollo/resources/records/<record_name> -l
   ```

> Note: Add -l if you want to play the data package in a loop; if you do not want to loop playback, there is no need to add -l.

### 8. Installation Directory Structure

At this point, the Apollo installation is complete.

The directory structure of the whole project is as follows:

```shell
application-core
├── .aem
│   └── envroot
│       ├── apollo          # Mounted to /apollo inside the container
│       └── opt             # Mounted to /opt/ inside the container; Apollo packages are installed under /opt/ by default, so this directory acts as a cache
├── core                    # Project dependency package
│   ├── BUILD
│   └── cyberfile.xml       # Package description file, describing all dependencies of the whole project
├── CPPLINT.cfg
├── data                    # Data directory, mounted to /apollo/data
│   ├── calibration_data    # Calibration configuration directory, mounted to /apollo/modules/calibration/data
│   ├── kv_db.sqlite
│   ├── log                 # Log directory, mounted to /opt/apollo/neo/data/log
│   └── map_data            # Map directory, mounted to /apollo/modules/map/data
├── profiles                # New configuration directory
│   ├── current -> sample   # Currently active configuration directory
│   └── sample              # Officially provided sample vehicle configuration with a single LiDAR and two cameras
├── third_party
├── tools -> /opt/apollo/neo/packages/bazel-extend-tools/latest/src
├── .vscode                 # Default vscode configuration
│   ├── c_cpp_properties.json
│   └── settings.json
├── WORKSPACE               # bazel configuration
└── .workspace.json         # Apollo project configuration, where you can specify package versions
```

## Step 6: Delete the Project (Optional)

This step explains how to delete an installed project.

### 1. Delete the Container

Take the `application-core` project as an example:

```shell
# First enter the project directory
cd application-core
# Delete the container
aem remove
```

### 2. Delete the Project

```shell
# Go back to the parent directory
cd ..
# Delete the project directory
rm -r application-core
```
