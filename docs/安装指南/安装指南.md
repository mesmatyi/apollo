## Notes

Apollo 11.0 is deployed with Docker containers. You can use Ubuntu 18.04, 20.04 or 22.04 on the x86_64 architecture, or Ubuntu 20.04 on the aarch64 architecture.

## Step 1: Install the Base Software

### 1. Install Ubuntu Linux

Apollo currently supports Ubuntu 18.04, Ubuntu 20.04 and Ubuntu 22.04. For installation steps, see the [official installation guide](https://ubuntu.com/tutorials/install-ubuntu-desktop).

After the installation is complete, update the related software:

```shell
sudo apt-get update
sudo apt-get upgrade
```

> Note: A network connection is required to complete the update.

### 2. Install Docker Engine

Apollo depends on Docker 19.03+. To install Docker Engine, you can follow the official documentation:

- See [Install Docker Engine on Ubuntu](https://docs.docker.com/engine/install/ubuntu/).

- You can also install it directly with the installation script provided by Apollo:

```shell
wget http://apollo-pkg-beta.bj.bcebos.com/docker_install.sh
bash docker_install.sh
```

The script may need to be run several times during this process. Just follow the prompts of the script.

## Step 2: Get GPU Support (Optional)

Some Apollo modules (for example, the perception module) require GPU support to be compiled and run. If you need to use such modules, you need to install the Nvidia graphics driver and the Nvidia
container toolkit to get GPU support.

> Note: This tutorial only applies to Ubuntu systems. Graphics drivers cannot be installed in virtual machines. For WSL, please search online for instructions.
> Note: If you have already installed the Nvidia graphics driver, that is, entering `nvidia-smi` in the terminal produces normal output, you can skip the `1. Install the driver` section.

**You can install the driver by following the method on the official website: [official driver page](https://www.nvidia.cn/drivers/unix/linux-amd64-display-archive/).**

### 2. Install the Nvidia Container Toolkit

To get GPU support inside containers, you need to install the NVIDIA Container Toolkit after installing Docker. Run the following commands to install the NVIDIA Container
Toolkit:

```shell
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg \
  && curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
    sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
    sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt-get -y update
sudo apt-get install -y nvidia-container-toolkit
```

After the installation is complete, configure the NVIDIA Container Toolkit:

```shell
sudo nvidia-ctk runtime configure --runtime=docker
```

After the configuration is complete, restart Docker:

```shell
sudo systemctl restart docker
```

## Step 3: Install the Apollo Environment Manager

The Apollo environment manager is a command-line tool that helps you manage and start the Apollo environment.

### 1. Install Dependencies

```shell
sudo apt-get update
sudo apt-get install ca-certificates curl gnupg
```

### 2. Add the Apollo Software Source gpg Key on the Host, Then Set Up the Source and Update

```shell
# Add the gpg key
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://apollo-pkg-beta.cdn.bcebos.com/neo/beta/key/deb.gpg.key | sudo gpg --dearmor -o /etc/apt/keyrings/apolloauto.gpg
sudo chmod a+r /etc/apt/keyrings/apolloauto.gpg

# Set up the source and update
echo \
    "deb [arch="$(dpkg --print-architecture)" signed-by=/etc/apt/keyrings/apolloauto.gpg] https://apollo-pkg-beta.cdn.bcebos.com/apollo/core"\
    $(. /etc/os-release && echo "$VERSION_CODENAME") "main" | \
    sudo tee /etc/apt/sources.list.d/apolloauto.list
sudo apt-get update
```

> Note: If you have previously installed Apollo 8.0, the `/etc/apt/sources.list` file on the host will contain an entry such as
> `deb https://apollo-pkg-beta.cdn.bcebos.com/neo/beta bionic main`, which you can delete directly. The Apollo source configuration on the host is only used to
> install the `aem` tool.

### 3. Install aem

```shell
sudo apt install apollo-neo-env-manager-dev --reinstall
```

After a successful installation, you can use

```shell
aem -h
```

## Step 4: Install a Sample Project

### 1. Choose a Sample Project

Apollo currently provides 3 sample projects. You can choose one according to your needs:

- [application-core](https://github.com/ApolloAuto/application-core): contains all Apollo open-source packages; you can build your own application on top of this project

- [application-pnc](https://github.com/ApolloAuto/application-pnc): contains only the planning and control packages, suitable for users who only focus on planning and control

- [application-perception](https://github.com/ApolloAuto/application-core): contains only the perception packages, suitable for users who only focus on perception

> You can also use [apollo](https://github.com/ApolloAuto/apollo), the project with the full Apollo source code.

> Note: Starting with Apollo 10.0, source mode and package mode use the same build tools. We recommend that you use the commands below consistently for building and running; the scripts such as dev_start.sh, dev_into.sh and apollo.sh in source mode are no longer recommended.

### 2. Clone the Project

Take application-core as an example:

```shell
git clone https://github.com/ApolloAuto/application-core.git application-core
```

### 3. Start and Enter the Apollo Environment

```shell
# First enter the project directory
cd application-core

# Switch the environment configuration. It automatically detects your host environment and switches the .env and .workspace.json configuration
# If you use the Apollo source mode, you do not need to run this step; aem automatically detects the startup environment
bash setup.sh

# Start the container
aem start
```

### 4. Install Software Packages

The sample project contains a directory named `core`, whose `core/cyberfile.xml` file describes the packages the project depends on. You can use the buildtool tool to install the dependency packages:

```shell
buildtool build -p core

# Note: if you want to compile and install all the code and packages in the working directory, run
buildtool build
```

> What this operation actually does is build the `core` package in the project, but `core` itself has no code to compile, so this operation only installs the dependency packages declared in `core/cyberfile.xml`.

> Note: The new version of buildtool adds the --opt --gpu parameters by default when building (if you use a GPU environment). If you need gdb debugging, build with the --dbg parameter.

### 5. Select the Vehicle Configuration

The profiles/sample directory in the sample project is the officially provided vehicle configuration based on one LiDAR and two cameras. You can refer to the sample under the profiles directory to write your own vehicle configuration. To activate a vehicle configuration:

```shell
# Take sample as an example
aem profile use sample
```

### 6. Play a Data Package

#### Get a Data Package

```shell
wget https://apollo-system.cdn.bcebos.com/dataset/6.0_edu/demo_3.5.record -P $HOME/.apollo/resources/records/
```

#### Get the Map Corresponding to the Data Package

```shell
buildtool map get sunnyvale
```

> Starting with version `9.0.0-rc-r10`, map data has been separated out and needs to be downloaded separately; it is no longer released with the package. You can view all available maps with `buildtool map list`.

#### Start Dreamview+

```shell
aem bootstrap start --plus
```

##### Play a Data Package in Dreamview+

After starting Dreamview+, enter `localhost:8888` in the browser to open the Dreamview+ interface. You can choose the default mode or another mode to play the data package. This section uses the default mode as an example.

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_alpha_doc/image_7deb2d2.png)

1. Select **Default Mode**.

2. Check **Accept the User Agreement and Privacy Policy**, and click **Enter this Mode** to enter the **Mode Settings** page.

3. On the **Mode Settings** page, set the playback parameters.
   
   - In **Operations**, select **Record**.
   - In **Environment Resources**, click **Records** and select the data package you want to play.
   - In **Environment Resources**, click **HDMap** and select **Sunnyvale Big Loop**.

4. Click the play button in the bottom area.
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Doc_CN_9_0/image_45acc2d.png)
   
   You can see the data package playback in **Vehicle Visualization**.

##### Play a Data Package from the Command Line

1. Enter the Docker environment.

2. In Dreamview+, first download the required data package under **Resource Manager** > **Records**. Then enter the following command to play the data package:
   
   ```bash
   cyber_recorder play -f ~/.apollo/resources/records/record_name -l
   ```

> Note: If you want to play the data package in a loop, add -l; if you do not want to loop playback, do not add -l.

### 8. Installation Directory Structure

At this point, the Apollo installation is complete.

The directory structure of the whole project is as follows:

```shell
application-core
├── .aem
│   └── envroot
│       ├── apollo          # Mounted to the /apollo directory in the container
│       └── opt             # Mounted to the /opt/ directory in the container. Apollo packages are installed under /opt/ by default, so this directory acts as a cache
├── core                    # Project dependency packages
│   ├── BUILD
│   └── cyberfile.xml       # Package description file, describes all dependencies of the project
├── CPPLINT.cfg
├── data                    # Data directory, mounted to /apollo/data
│   ├── calibration_data    # Calibration configuration directory, mounted to /apollo/modules/calibration/data
│   ├── kv_db.sqlite
│   ├── log                 # Log directory, mounted to /opt/apollo/neo/data/log
│   └── map_data            # Map directory, mounted to /apollo/modules/map/data
├── profiles                # New-style configuration directory
│   ├── current -> sample   # Currently enabled configuration directory
│   └── sample              # Officially provided sample vehicle configuration with a single LiDAR and two cameras
├── third_party
├── tools -> /opt/apollo/neo/packages/bazel-extend-tools/latest/src
├── .vscode                 # Default vscode configuration
│   ├── c_cpp_properties.json
│   └── settings.json
├── WORKSPACE               # bazel configuration
└── .workspace.json         # Apollo project configuration, where you can specify package versions
```

## Step 5: Remove the Project (Optional)

This step describes how to remove an installed project.

### 1. Remove the Container

Take the `application-core` project as an example:

```shell
# First enter the project directory
cd application-core
# Remove the container
aem remove
```

### 2. Remove the Project

```shell
# Go back to the parent directory
cd ..
# Delete the project directory
rm -r application-core
```
