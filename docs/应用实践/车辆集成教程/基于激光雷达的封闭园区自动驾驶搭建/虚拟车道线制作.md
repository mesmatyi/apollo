## Prerequisites

1. Complete [LiDAR-Based Closed-Campus Autonomous Driving Setup -- Perception Device Calibration](../应用实践/车辆集成教程/基于激光雷达的封闭园区自动驾驶搭建/感知设备标定.md).

2. Complete the [Cloud Service Account Activation Guide](https://apollo.baidu.com/Apollo-Homepage-Document/Vehicle_Nameplate/三、开通Fuel云服务/3.%20开通Fuel研发云服务账号).

## Step 1: Record the Virtual Lane Line Data Package

Record a data package of the area where you want autonomous driving in advance as required, to serve as the input data for generating the virtual lane lines later.

> Note: The data package size is currently limited to no more than 5 GB.

The required channel information is as follows:

| No. | topic                                      |
| ---- | ------------------------------------------ |
| 1    | /apollo/localization/pose                  |
| 2    | /apollo/sensor/gnss/odometry               |
| 3    | /apollo/sensor/gnss/ins_stat               |
| 4    | /apollo/sensor/40p/compensator/PointCloud2 |

To obtain the above `channel`s, the three modules `GPS`, `Localization` and `Velodyne` need to be started.

- For starting the `GPS` and `Localization` modules, refer to the localization module configuration document.

- For starting the `Velodyne` module, refer to the perception sensor integration document.

To save data space, it is recommended to record the data package from the command line in the docker environment rather than with the `Recorder` module. The recording command is as follows:

```
 cyber_recorder record -c /apollo/localization/pose /apollo/sensor/gnss/odometry /apollo/sensor/gnss/ins_stat /apollo/sensor/40p/compensator/PointCloud2
```

> Note: Before recording data, first make sure `enable_lidar_localization` in the `modules/localization/conf/localization.conf` file is set to `false`; after the map is created, if msf localization is needed, change it to true.

## Step 2: Generate the Virtual Lane Lines with the Virtual Lane Line Cloud Service

### 1. Upload the Data to BOS

> Note: You must use the Bos bucket whose user account information was submitted in Dreamland. Confirm that the `Bos bucket name`, `Bos region`, `Bos access key` and `Bos secret key` are correct.

Create a new directory `virtual_lane` in the BOS bucket to serve as the `Input Data Path` from which the subsequent cloud calibration service reads data, and copy the previously recorded data package and the `lidar_GNSS` extrinsic file into this directory. The directory structure is shown in the figure:

![virtual_lane_tree1](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/154fdb28aa1ae132e64c80cd3aef9942.png)

### 2. Submit the Virtual Lane Line Generation Task

1. Click the **Tasks** menu item under **Apollo Fuel** in the left menu bar to enter the task management page.

2. Click **New Task** and select the virtual lane line service in the drop-down box that appears, as shown in the figure below:

   ![virtual_lane_fuel](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/e7092b0aa3b3c66b99bf6398fa48c61a.png)

   - Fill in the input data path (`virtual_lane` in this example),

   - Fill in the output data path (the map generation path, `result` in this example),

   - Fill in the zone number (fill it in according to your local situation; the location in this example is Beijing, so enter `50`),

   - Fill in the LiDAR type (the LiDAR type of the `/apollo/sensor/lidar16/compensator/PointCloud2` channel you configured; in this example it is `lidar16`),

   - Fill in the lane width (the width of the lane lines; `3.3` in this example),

   - Fill in the extra ROI expansion (the distance from the lane line boundary to the real road edge; `0.5` in this example).

3. Click **Submit Task**.

> Note: The bos must have write permission, and the zone number passed in must be consistent with the value of the `local_utm_zone_id` configuration item in the `localiztion.conf` configuration file used when the data package was recorded.

### 3. Obtain the Virtual Lane Lines and Add Them to Apollo

After the task completes, you will receive an email in your registered mailbox:

![virtual_lane_email](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/5fd17fb449b843c97b7ac485bfa8f559.png)

If the email content is as shown in the figure above, the virtual lane lines were generated successfully. Check the Output Data Path on bos (`result` in this example); the directory structure of this path is shown in the figure below:

![virtual_lane_tree2](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/ae0b2fcb700303179005ff3aa51f3352.png)

Copy the whole `2020-01-16-08-08-42` folder in the figure above to `/apollo/modules/map/data/` and rename it to your map name (for example: gongyuan). Restart DreamView and you will see the newly added map in the map drop-down box.

## FAQ

### The local_map folder is not generated in BOS

Confirm that the `--local_utm_zone_id` option in the `/apollo/modules/localization/conf/localization.conf` file is consistent with the `zone_id` passed in when submitting the virtual lane line cloud service.

### The map generated in BOS has problems

While recording the virtual lane line data package, the vehicle may only drive the predetermined road once and must not form a closed loop.

### No map data is generated in BOS

Confirm that the BOS information given when the account was submitted is correct.
