This user manual aims to help users complete the configuration and open-loop verification of the planning module. The planning module requires perception data from upstream. There are currently two perception schemes, Lidar perception and Camera perception, and you can choose either one.

## Prerequisites

1. Complete [LiDAR-Based Closed-Campus Autonomous Driving Setup -- Perception Adaptation](../应用实践/车辆集成教程/基于激光雷达的封闭园区自动驾驶搭建/感知适配.md) or [Camera-Based Closed-Campus Autonomous Driving Setup -- Perception Adaptation](../应用实践/车辆集成教程/基于摄像头的封闭园区自动驾驶搭建/感知适配.md).

2. Complete [Closed-Campus Autonomous Driving Setup -- Virtual Lane Line Creation](../应用实践/车辆集成教程/基于激光雷达的封闭园区自动驾驶搭建/虚拟车道线制作.md).

## Step 1: Modify the Configuration Files

Make the following modifications to the two configuration files `/apollo/modules/planning/conf/planning.conf` and `/apollo/modules/planning/conf/planning_config.pb.txt`:

| File Name                 | Parameter                                                     | Unit            | Description                                   |
| ------------------------ | -------------------------------------------------------- | --------------- | -------------------------------------- |
| `planning.conf`          | Modify the value of `default_cruise_speed`. Example value: 1.5            | m/s             | Default cruise speed                           |
| `planning.conf`          | Modify the value of `planning_upper_speed_limit`. Example value: 1.5      | m/s             | Maximum speed of the vehicle in planning                   |
| `planning.conf`          | Add the value of `planning_lower_speed_limit`. Example value: 0.5      | m/s             | Minimum speed of the vehicle in planning                   |
| `planning.conf`          | Add the value of `speed_upper_bound`. Example value: 1.5               | m/s             | Maximum speed of the vehicle                             |
| `planning.conf`          | Add the value of `max_stop_distance_obstacle`. Example value: 10       | m               | Maximum stopping distance from obstacles                     |
| `planning.conf`          | Add the value of `min_stop_distance_obstacle`. Example value: 5        | m               | Minimum stopping distance from obstacles                     |
| `planning.conf`          | Add the value of `destination_check_distance`. Example value: 1.0      | m               | Distance between the vehicle and the destination at which the vehicle is considered to have reached the destination |
| `planning.conf`          | Add the value of `lon_collision_buffer`. Example value: 0.3            | m               | Default collision distance between the vehicle and obstacles               |
| `planning.conf`          | Add the `enable_scenario_park_and_go` configuration item. Example value: false | -               | Disables the park-and-go (start-from-parking) scenario                     |
| `planning_config.pb.txt` | Modify the value of `total_time`. Example value: 15.0                     | s               | How long a route planning plans                  |
| `planning_config.pb.txt` | Modify the value of `max_acceleration`. Example value: 1.0                | m/s<sup>2</sup> | Maximum acceleration of the vehicle                         |
| `planning_config.pb.txt` | Modify the value of `lowest_speed`. Example value: 0.5                    | m/s             | Lowest speed of the vehicle during planning                |
| `planning_config.pb.txt` | Modify the value of `max_speed_forward`. Example value: 1.5               | m/s             | Maximum forward speed of the vehicle                       |
| `planning_config.pb.txt` | Modify the value of `max_acceleration_forward`. Example value: 1.0        | m/s<sup>2</sup> | Maximum forward acceleration of the vehicle                     |

> Note: The configuration takes effect after the planning module is restarted. For safety, the planning speed must be set quite low; it is recommended that you set the corresponding configuration parameters to the values given above.

## Step 2: Startup Procedure

Drive the vehicle outdoors, control it manually, and, while the perception shows obstacle information, add routing points and check whether there is planning trajectory line information.

### 1. Press the Emergency Stop Switch at the Rear of the Vehicle

The purpose of this document is to adapt planning and complete the open-loop verification of the planning module, which does not require the vehicle to move. For safety, after driving the vehicle to the outdoor debugging site, make sure the emergency stop switch stays pressed throughout.

### 2. Start Perception

Start the perception module; see [Perception Adaptation](../应用实践/车辆集成教程/基于激光雷达的封闭园区自动驾驶搭建/感知适配.md '_self').

### 3. Start the Planning, Prediction and Control Modules

After making sure the perception module has started successfully, start the `Planning`, `Prediction` and `Control` modules in the `Modules` tab. The modules shown as started on DreamView+ are as shown in the figure below:

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_6d30cb0.png)

### 4. Verify That the Planning, Prediction and Control Modules Started Successfully

1. In the vehicle visualization panel, click Routing Editing and select the start point and waypoints.

2. Click **Save Editing**.

   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_9b9860a.png)

3. Click the **Send Routing** button.

   In DreamView+, a blue line and a red stop sign appear.

   When there is a person or bicycle (with a rider) in front of the vehicle, view the planning trajectory line in the **Vehicle Visualization panel**; normally planning will replan the trajectory, as shown in the figure below:

   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_f7bbf89.png)

Enter the command `cyber_monitor` in the docker environment and view the planning channel information:

![lidar_demonstration_channel](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/37aad4eb3d789c3ff843fa437a9157a8.png)

If the trajectory line and topic information shown in the figure above appear, the planning module adaptation and open-loop test have passed. Otherwise, continue to check the log information for debugging.
