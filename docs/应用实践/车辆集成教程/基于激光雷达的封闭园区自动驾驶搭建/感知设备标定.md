This user manual aims to help users complete the calibration of the LiDAR (Lidar-GNSS).

## Prerequisites

1. Complete [Record-and-Replay Setup -- Vehicle Record-and-Replay Demonstration](../应用实践/车辆集成教程/循迹搭建/车辆循迹演示.md).

2. Complete [LiDAR-Based Closed-Campus Autonomous Driving Setup -- Perception Device Integration](../应用实践/车辆集成教程/基于激光雷达的封闭园区自动驾驶搭建/感知设备集成.md).

3. Complete the [Cloud Service Account Activation Guide](https://apollo.baidu.com/Apollo-Homepage-Document/Vehicle_Nameplate/三、开通Fuel云服务/3.%20开通Fuel研发云服务账号).

### Manually Measure the Initial Lidar-GNSS Extrinsics

It is assumed here that the user has installed the sensors correctly as required by the perception device integration document, that is, the sensor coordinate system definitions are the same as those above and the installation error meets the requirements in the document.

- rotation: when the sensor installation meets the above installation requirements, the user does not need to measure this value and can use the following default value directly.

  ```txt
    rotation:
      w: 0.7071
      x: 0.0
      y: 0.0
      z: 0.7071
  ```

- translation: the user needs to manually measure the displacement transformation with the IMU coordinate system as the base coordinate system and the LiDAR coordinate system as the target coordinate system. An example of an IMU-Lidar displacement transformation is as follows:

  ```txt
    translation:
      x: 0.0
      y: 0.38
      z: 1.33
  ```

## Step 3: Select the Calibration Site

The calibration site directly affects the calibration result. The calibration site has the following requirements:

- Within 8 meters of the center of the calibration site there must be static reference objects with clear outlines, such as utility poles, buildings and vehicles; avoid too many dynamic obstacles. If the static obstacles are far away, the calibration result will be seriously affected.

- Make sure the road surface is flat.

- Make sure the GNSS signal is good, without too much interference.

## Step 4: Collect Data with Fuel-Client

### 1. Select the Correct Mode and Vehicle Model

1. Select the `Lidar-IMU Sensor Calibration` mode.

2. Select the correct vehicle model according to the actual situation.

   ![1.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Doc_CN_6_0/1_0caa8d8.png)

### 2. Start Fuel Client and Start the Corresponding Modules

1. Under the `Tasks` tab of DreamView, turn on `Sim Control`.

2. Turn on `Fuel Client`.

> Note: After `Fuel Client` is turned on, be sure to turn off `Sim Control`.

    ![1.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Doc_CN_6_0/1_bd85dab.png)

3. Under the `Module Controllers` tab of DreamView, start the `GPS`, `Lidar` and `Localization` modules. When `GPS`, `Lidar` and `RTK` in the module status display on the left are all green, the modules have started successfully.

> Note: After Localization starts, wait 1 to 2 minutes before it outputs data normally.

![1.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Doc_CN_6_0/1_15d0247.png)

### 3. Start the Recorder Module and Begin Collecting

- When `GPS`, `Lidar` and `RTK` in the module status display on the left are all green, turn on the `Recorder` module and begin collecting data. Drive the vehicle slowly in a figure-8 trajectory with the turning radius as small as possible, covering 2 to 3 complete laps of the figure-8 trajectory.

![lidar_calibration_turn_around](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/9a1bdc4dfdb96585db3a9c4cd9411965.png)

- After the data collection is complete, turn off the `Recorder` module to stop recording.

## Step 5: Preprocess the Data with Fuel Client

![1.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Doc_CN_6_0/1_af63894.png)

1. Click `Configuration` in the upper right corner to enter the preprocessing interface.

2. Fill in the measured initial extrinsics.

3. Click `Preprocess` to preprocess.

   Wait for the preprocessing to finish; the message `Data extraction is completed successfully!` indicates that preprocessing is complete.

> Note: For users with 3 LiDARs, the initial extrinsics of all 3 LiDARs must be filled in; the extrinsics of the red `lidar16_back` are those of the `main_sensor` (the main LiDAR).

![1.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Doc_CN_6_0/1_44c34ae.png)

4. Save the generated preprocessed files. Switch to the `apollo/output/sensor_calibration/lidar_to_gnss/extracted_data/` directory and save the `lidar_to_gnss-xxx` file in that directory (`xxx` is the time the data package was recorded). Here and below, `lidar_to_gnss-2021-01-12-14-10` is used as the example.

## Step 6: Generate the Extrinsic File with the Calibration Cloud Service

### 1. Upload the Preprocessed Data to BOS

> Note: You must use a bucket that has been granted permission. Confirm that the `Bucket Name` and `Region` are consistent with the Bucket name and region submitted when registering with the business department.

Upload the `lidar_to_gnss-2021-01-12-14-10` directory to the root directory of BOS, to serve as the `input data path` from which the subsequent cloud calibration service reads data.

### 2. Submit the Cloud Calibration Task

1. Open the Apollo cloud service page.

2. Click **Apollo Fuel** > **Tasks**.

3. Click **New Task**.

![fuel_new_task](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/78f28add5ffcca20b38b547db16292b1.png)

4. Select **Perception Calibration** from the drop-down box.

   - Enter the **Input Data Path** according to the actual situation; `lidar_to_gnss-2021-01-12-14-10` is used as the example here.
   - Specify the **Output Data Path**.

5. Click the **Submit Job** button to submit.

   ![sensor_calibration_fuel](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/fd6b2d735012fe35b66f50ea4447576d.jpg)

### 3. Obtain the Calibration Result Verification and the Calibration Extrinsic File

After the cloud calibration task completes, you will receive a calibration result email in your registered mailbox. If the calibration task succeeds, it will contain the calibration extrinsic file.

**Lidar-GNSS Calibration Result Verification**:

- The **output file path** specified by the user in BOS contains point cloud files with the suffix `.pcd`. Check the pcd files with a point cloud viewing tool. If the surrounding obstacles in the point cloud file are clear and sharp with neat edges, the calibration result is accurate; otherwise please recalibrate.

![lidar_calibration_point_cloud](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/dcfdc92e79a693d42045638154d8f26e.png)

- On Ubuntu, the `pcl-tools` tool can be used to view point cloud files:

```bash
  sudo apt-get update
  sudo apt-get install pcl-tools
  pcl_viewer xxx.pcd
```

**Lidar-GNSS Calibration Extrinsic File**:

After confirming that the obtained extrinsic file is reasonable, replace the `rotation` and `translation` values in `modules/calibration/data/车型目录/lidar_params/velodyne16_novatel_extrinsics.yaml` with the `rotation` and `translation` values of the obtained extrinsic file. Be careful not to modify `frame_id` and not to replace the file directly.

## FAQ

### After running the Sensor Calibration task, the email says the task failed

It is recommended to check whether the input path is correct.

### The calibration result is poor

- During calibration, make sure the GNSS signal status is good and there are static obstacles with clear outlines around.

- Ensure the installation accuracy of the sensors; when the installation error exceeds the required accuracy, the calibration result does not converge easily.

- During calibration, do not stay too far away from valid static obstacles.
