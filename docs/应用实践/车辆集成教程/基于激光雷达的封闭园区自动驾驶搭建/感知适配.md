This user manual aims to help users complete the LiDAR perception adaptation and enable Lidar perception.

## Prerequisites

1.  Complete [Record-and-Replay Setup -- Vehicle Record-and-Replay Demonstration](../应用实践/车辆集成教程/循迹搭建/车辆循迹演示.md).

2.  Complete [LiDAR-Based Closed-Campus Autonomous Driving Setup -- Perception Device Integration](../应用实践/车辆集成教程/基于激光雷达的封闭园区自动驾驶搭建/感知设备集成.md).

3.  Complete [LiDAR-Based Closed-Campus Autonomous Driving Setup -- Perception Device Calibration](../应用实践/车辆集成教程/基于激光雷达的封闭园区自动驾驶搭建/感知设备标定.md).

## Step 1: Start Perception

Drive the vehicle outdoors and start Lidar perception.

### 1. Build the Project and Start Dreamview+

#### 1) Start the Apollo Docker Environment

If you are using package management, follow these steps:

1. Open a command-line terminal and change the path to Apollo:

   ```bash
   cd ~/apollo
   ```

2. Enter the following commands to enter the Apollo Docker environment:

   ```bash
   aem start # create the container
   aem enter # enter the container
   buildtool build
   ```

   > Note: Use `buildtool build` the first time you enter the container; if you only want to build the updated modules, use the following command `buildtool build -p module_name`.

   If your terminal looks like the one below, you have successfully entered Apollo's runtime container:

   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_7e7a575.png)

If you are using source code, follow these steps to enter the docker environment:

1. Open a command-line terminal and change the path to Apollo:

   ```bash
   cd ~/apollo     # change the path to apollo; note there is a space between cd and ~/apollo
   ```

2. Enter the following command to start the Apollo Docker environment:

   ```bash
   bash docker/scripts/dev_start.sh
   ```

   Start the docker environment:

   ```bash
   bash docker/scripts/dev_into.sh
   ```

   If your terminal looks like the one below, you have successfully entered Apollo's runtime container:

   ```bash
   [user@in-runtime-docker:/apollo]$
   ```

#### 2) Start and Open Dreamview+

You can start Dreamview+ through package management or from source. Choose one method and start Dreamview+ with the corresponding commands.

- Method 1: Package Management

  Enter the docker environment through package management, and run the following command in the docker environment to start Dreamview+:

  ```bash
  aem bootstrap start --plus
  ```

  > Note:
  >
  > - If you want to stop Dreamview+, enter `aem bootstrap stop --plus`,
  > - If you want to restart Dreamview+, enter `aem bootstrap restart --plus`.

- Method 2: Source Code

  Enter the docker environment from source, and run the following command in the docker environment to start Dreamview+:

  ```bash
  bash scripts/bootstrap.sh start_plus
  ```

  > Note:
  >
  > - If you want to stop Dreamview+, enter `bash scripts/bootstrap.sh stop_plus`,
  > - If you want to restart Dreamview+, enter `bash scripts/bootstrap.sh restart_plus`.

After it starts successfully, enter `localhost:8888` in the browser to open the Dreamview+ interface.

### 2. Start the Required Modules

1. Open `(http://localhost:8888)` in the browser.

2. Select the `Vehicle Test` mode.

3. Select the corresponding vehicle model according to the actual situation.

4. In the `Module Controller` tab, start the Canbus, GPS, Localization and Transform modules.

   After the localization module starts, it needs to receive localization data, which takes about 1 minute.

5. Open a new terminal and enter the docker environment. In the new terminal, enter the `cyber_monitor` command to view the channel data related to each module.

   When all three show green in cyber_monitor, the localization module has started successfully.

   ![lidar_integration_localization_check](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/a36b9d903205c7dd0cfc35add9f201fe.png)

6. Start the `lidar` module in Dreamview.

7. Check whether the lidar data is correct.

   Use `cyber_monitor` to check whether the LiDAR-related channels are output normally,

   - Use the Up/Down arrow keys to select a channel,

   - Use the Right arrow key to view the detailed channel data.

   For users with a single LiDAR, check whether the following channels are output normally:

   | No. | channel                                      | Frame Rate |
   | ---- | -------------------------------------------- | ---- |
   | 1    | `/apollo/sensor/40p/PointCloud2`             | 10Hz |
   | 2    | `/apollo/sensor/40p/Scan`                    | 10Hz |
   | 3    | `/apollo/sensor/40p/compensator/PointCloud2` | 10Hz |

## Step 2: Verify the Perception Results

Look at a person or bicycle moving 10 meters in front of the vehicle (there must be a rider on the bicycle), and view the obstacle color and position/speed information on DreamView+, as shown in the figure below:

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_a4e033d.png)

The data of `/apollo/perception/obstacles` is shown in the figure below:

![lidar_adaptation_obstacles1](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/02d441b2c1aed3836f1a84b88ccd898b.png)

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_a2100fc.png)

If obstacles can be seen on DreamView+ and `/apollo/perception/obstacles` contains obstacle information, the open-loop test passes.
