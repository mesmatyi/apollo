This user manual aims to help users complete the installation, integration and data verification of the LiDAR perception device.

## Prerequisites

Complete [Record-and-Replay Setup -- Vehicle Record-and-Replay Demonstration](../应用实践/车辆集成教程/循迹搭建/车辆循迹演示.md).

## LiDAR Installation and Data Verification

![banner-pic.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo-D-KIT-CN/banner-pic_dac1b06.png)

### 1. Install and Fix the LiDAR

The LiDAR must be firmly fixed on the roof of the vehicle. It is recommended that the LiDAR height above the ground be 1.5 to 1.8 meters, mounted level with an accuracy within 2 degrees. The installation position is shown below:

![IMG_2450.JPG](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo-D-KIT-CN/IMG_2450_c6ef4d6.JPG)

### 2. Configure the LiDAR

Modify the IP address of the industrial PC:

1. The LiDAR is connected to the industrial PC through an Ethernet cable. Change the IP of this industrial PC port to the fixed IP address `192.168.1.100`, and set the subnet mask to `255.255.255.0`.

![1.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Doc_CN_6_0/1_2cc21e8.png)

2. Enter `192.168.1.201` in the browser and confirm that the LiDAR's Destination Lidar Port is 1368 and Destination Gps Port is 10110.

![1.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo-D-KIT-CN/1_e36066c.png)

### 3. Verify the LiDAR Data

#### 1) Start the Apollo Docker Environment

If you are using package management, follow these steps:

1. Open a command-line terminal and change the path to Apollo:
   
   ```bash
   cd ~/apollo
   ```

2. Enter the following commands to enter the Apollo Docker environment:
   
   ```bash
   aem start # create the container
   aem enter # enter the container
   buildtool build
   ```
   
   > Note: Use `buildtool build` the first time you enter the container; if you only want to build the updated modules, use the following command `buildtool build -p module_name`.
   
   If your terminal looks like the one below, you have successfully entered Apollo's runtime container:
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_7e7a575.png)

If you are using source code, follow these steps to enter the docker environment:

1. Open a command-line terminal and change the path to Apollo:
   
   ```bash
   cd ~/apollo     # change the path to apollo; note there is a space between cd and ~/apollo
   ```

2. Enter the following command to start the Apollo Docker environment:
   
   ```bash
   bash docker/scripts/dev_start.sh
   ```
   
   Start the docker environment:
   
   ```bash
   bash docker/scripts/dev_into.sh
   ```
   
   If your terminal looks like the one below, you have successfully entered Apollo's runtime container:
   
   ```bash
   [user@in-runtime-docker:/apollo]$
   ```

#### 2) Start and Open Dreamview+

You can start Dreamview+ through package management or from source. Choose one method and start Dreamview+ with the corresponding commands.

- Method 1: Package Management
  
  Enter the docker environment through package management, and run the following command in the docker environment to start Dreamview+:
  
  ```bash
  aem bootstrap start --plus
  ```
  
  > Note:
  > 
  > - If you want to stop Dreamview+, enter `aem bootstrap stop --plus`,
  > - If you want to restart Dreamview+, enter `aem bootstrap restart --plus`.

- Method 2: Source Code
  
  Enter the docker environment from source, and run the following command in the docker environment to start Dreamview+:
  
  ```bash
  bash scripts/bootstrap.sh start_plus
  ```
  
  > Note:
  > 
  > - If you want to stop Dreamview+, enter `bash scripts/bootstrap.sh stop_plus`,
  > - If you want to restart Dreamview+, enter `bash scripts/bootstrap.sh restart_plus`.

After it starts successfully, enter `localhost:8888` in the browser to open the Dreamview+ interface.

#### 3) Start the Required Modules.

1. Open `(http://localhost:8888)` in the browser.
2. Select the **Vehicle Test** mode.
3. Select the corresponding vehicle model according to the vehicle nameplate information.
4. In **Modules**, start the `GPS`, `Localization` and `Transform` modules.

After the localization module starts, it needs to receive localization data, which takes about 1 minute.

5) Open a new terminal and enter the docker environment.

6) In the new terminal, enter the `cyber_monitor` command to view the `tf`, `tf_static` and `/apollo/localization/pose` data. When all three show green in `cyber_monitor`, the localization module has started successfully.

![lidar_integration_localization_check](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/a36b9d903205c7dd0cfc35add9f201fe.png)

7) Start the `lidar` module in DreamView+.

#### 4) Check whether the lidar data is correct.

Use `cyber_monitor` to check whether the LiDAR data is output normally.

- Use the Up/Down arrow keys to select a channel,
- Use the Right arrow key to view the detailed channel data. If the data is normal, the LiDAR adaptation succeeded.

For users with a single LiDAR, check whether the following channels are output normally:

| No.  | channel                                           | Frame Rate   |
| --- | ------------------------------------------------- | ---- |
| 1   | `/apollo/sensor/hesai40p/PointCloud2`             | 10Hz |
| 2   | `/apollo/sensor/hesai40p/Scan`                    | 10Hz |
| 3   | `/apollo/sensor/hesai40p/compensator/PointCloud2` | 10Hz |

![lidar_integration_cyber_monitor](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/c5da579fc5cf086eaed731caf69b5a8c.png)

## Millimeter-Wave Radar Installation and Data Verification (Configure as Needed)

> Note: The current perception scheme does not fuse millimeter-wave radar data, so users with no secondary development needs can skip configuring the millimeter-wave radar; if you have secondary development needs, you can configure the millimeter-wave radar following this section.

- Millimeter-wave radar model: continental AS 408-21

- Introduction to continental AS 408-21: The ARS408-21 is the latest high-end product in Continental's 40X millimeter-wave radar sensor series and is suitable for different application scenarios. The ARS 408-21 reconciles the contradiction between measurement performance and high safety well: it can detect the distance to targets in real time and, based on the current vehicle speed, judge whether there is a collision risk reliably; it has an automatic fault detection function that can identify sensor problems and automatically output fault codes; and it has a robust, lightweight design. By using relatively simple radar measurement technology, and on the basis of in-depth R&D and mass production experience in the automotive industry, the product can be guaranteed to have robust and lightweight performance.
  
  ![lidar_integration_radar_look](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/a416478339c553cfebb0d72ffb2ca513.jpg)

### 1. Millimeter-Wave Radar Interface and Wiring Order

The continental AS 408-21 sensor is powered by 12 V DC and uses a CAN communication interface. In use, connect the sensor's CAN communication interface to Apollo's CAN1 port with the connection cable shown in the figure below, and connect the power interface to a 12 V DC power supply (the vehicle provides a 12 V power junction box), paying attention to polarity.

![lidar_integration_radar_line](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/f4f043616917407f2956062bac5882e9.png)

The sensor interface and definitions are shown in the figure below, where:

- Port 1 connects to 12 V DC power;

- Port 8 connects to GND;

- Port 4 connects to CAN_L;

- Port 7 connects to CAN_H;

- The millimeter-wave radar CAN interface connects to the millimeter-wave radar CAN interface of the industrial PC.
  
  ![lidar_integration_radar_picture](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/f6f6debe85bdd0b23730b36dd5addd34.png)
  
  ![lidar_integration_radar_pin](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/3ca81d78493fac8f8d4a5c4150b75948.png)

### 2. Install and Fix the Millimeter-Wave Radar

The millimeter-wave radar must be firmly fixed on the vehicle body, and the connector to the millimeter-wave radar must be plugged in securely. Mount it 0.5 meters above the ground, not tilted downward, with an upward pitch within 0-2 degrees; the height error is ±0.2 meters, the pitch angle error is 0-2 degrees (tilted up by less than 2 degrees, never tilted down), the roll angle error is ±2 degrees (how level the left and right sides of the radar are), and the heading angle error is ±2 degrees (whether the radar faces straight ahead).

![IMG_2450.JPG](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo-D-KIT-CN/IMG_2450_c6ef4d6.JPG)

### 3. Configure and Start the Millimeter-Wave Radar

#### Millimeter-Wave Radar Configuration

Since only the front millimeter-wave radar is used, the configuration related to the rear millimeter-wave radar (rear components) must be deleted from the configuration file `modules/drivers/radar/contiradar/dag/conti_radar.dag`. Otherwise, because the rear millimeter-wave radar uses can 2 while our socket can has no can 2, canbus will fail to start normally. The content of the modified `conti_radar.dag` file is as follows:

```
module_config {
    module_library : "/apollo/bazel-bin/modules/drivers/radar/conti_radar/libconti_radar.so"
    components {
        class_name : "ContiRadarCanbusComponent"
        config {
            name: "conti_radar_front"
            config_file_path:  "/apollo/modules/drivers/radar/conti_radar/conf/radar_front_conf.pb.txt"
        }
    }
}
```

#### Starting the Millimeter-Wave Radar

1. Start Apollo and DreamView correctly.

2. Select the mode according to the actual situation.

3. Select the corresponding vehicle model according to the vehicle nameplate information, and turn on the `radar` module switch.

4. Use the `cyber_monitor` tool to view the `/apollo/sensor/radar/front` data.
   
   ![lidar_integration_radar_rostopic2](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/8884274329bcab4fe8bf0b7e2b00c767.png)
   
   ![lidar_integration_radar_rostopic3](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/2e860856f27988f8b8cb1be424fefbf7.png)
   
   ![lidar_integration_radar_rostopic4](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/ee545f633e9f101eae3c56efc04e1152.png)
   
   The meanings of the main parameters are shown in the table below:
   
   | Parameter               | Meaning       |
   | ---------------- | -------- |
   | `longitude_dist` | Longitudinal distance to the target |
   | `lateral_dist`   | Lateral distance to the target |
   | `longitude_vel`  | Longitudinal velocity of the target  |
   | `lateral_vel`    | Lateral velocity of the target  |

### 4. Verify the Millimeter-Wave Radar Data

- Verification of longitudinal distance (`longitude_dist`) / lateral distance (`lateral_dist`): the sensor uses the `long range` mode by default, with a detection range of 0.2 to 250 m. Place obstacles within the detection range directly in front of the vehicle and check whether the `longitute_dist` and `lateral_dist` data in the `/apollo/sensor/conti_radar` topic are normal (unit: m). The red part in the figure below is the sensor detection range in long-range mode; an error within +/-0.4 m is normal.
  
  ![lidar_integration_radar_verify_picture](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/bf634189ae4cf2332c23c3174691decd.png)

- Verification of longitudinal velocity (`longitude_vel`) / lateral velocity (`lateral_vel`): make the target object move at a fixed speed within the detection range and check whether the detected data is within the allowable error range.

The measurement range and resolution of each parameter of this sensor are shown in the figure below:

## FAQ

### Unable to open the Lidar configuration web page

Generally, as long as the Lidar IP and the IP of the network port connecting the computing unit (HW3.0) to the Lidar are in the same network segment, the configuration web page can be opened in the browser. If you have confirmed that the local IP has been modified correctly and the configuration page still cannot be opened, check whether the Lidar's IP address has been changed; you can download `wireshark` to view the Lidar IP.
