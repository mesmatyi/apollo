This user manual aims to help users complete closed-campus autonomous driving based on Camera perception.

## Prerequisites

1. Complete [Camera-Based Closed-Campus Autonomous Driving Setup -- Perception Device Integration](../应用实践/车辆集成教程/基于摄像头的封闭园区自动驾驶搭建/感知设备集成.md).

2. Complete [Camera-Based Closed-Campus Autonomous Driving Setup -- Perception Adaptation](../应用实践/车辆集成教程/基于摄像头的封闭园区自动驾驶搭建/感知适配.md).

3. Complete [Closed-Campus Autonomous Driving Setup -- Virtual Lane Line Creation](../应用实践/车辆集成教程/基于激光雷达的封闭园区自动驾驶搭建/虚拟车道线制作.md).

4. Complete [Closed-Campus Autonomous Driving Setup -- Planning Adaptation](../应用实践/车辆集成教程/基于激光雷达的封闭园区自动驾驶搭建/规划适配.md).

5. Make sure to experiment in relatively safe conditions, such as level roads with few vehicles and people.

6. Make sure at least two people operate: one operates the vehicle as the safety driver and one operates autonomous driving, with the safety driver ready to take over at any time.

## Startup Procedure

### 1. Build the Project and Start DreamView+

#### 1) Start the Apollo Docker Environment

If you are using package management, follow these steps:

1. Open a command-line terminal and change the path to Apollo:

   ```bash
   cd ~/apollo
   ```

2. Enter the following commands to enter the Apollo Docker environment:

   ```bash
   aem start # create the container
   aem enter # enter the container
   buildtool build
   ```

   > Note: Use `buildtool build` the first time you enter the container; if you only want to build the updated modules, use the following command `buildtool build -p module_name`.

   If your terminal looks like the one below, you have successfully entered Apollo's runtime container:

   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_7e7a575.png)

If you are using source code, follow these steps to enter the docker environment:

1. Open a command-line terminal and change the path to Apollo:

   ```bash
   cd ~/apollo     # change the path to apollo; note there is a space between cd and ~/apollo
   ```

2. Enter the following command to start the Apollo Docker environment:

   ```bash
   bash docker/scripts/dev_start.sh
   ```

   Start the docker environment:

   ```bash
   bash docker/scripts/dev_into.sh
   ```

   If your terminal looks like the one below, you have successfully entered Apollo's runtime container:

   ```bash
   [user@in-runtime-docker:/apollo]$
   ```

#### 2) Start and Open Dreamview+

You can start Dreamview+ through package management or from source. Choose one method and start Dreamview+ with the corresponding commands.

- Method 1: Package Management

  Enter the docker environment through package management, and run the following command in the docker environment to start Dreamview+:

  ```bash
  aem bootstrap start --plus
  ```

  > Note:
  >
  > - If you want to stop Dreamview+, enter `aem bootstrap stop --plus`,
  > - If you want to restart Dreamview+, enter `aem bootstrap restart --plus`.

- Method 2: Source Code

  Enter the docker environment from source, and run the following command in the docker environment to start Dreamview+:

  ```bash
  bash scripts/bootstrap.sh start_plus
  ```

  > Note:
  >
  > - If you want to stop Dreamview+, enter `bash scripts/bootstrap.sh stop_plus`,
  > - If you want to restart Dreamview+, enter `bash scripts/bootstrap.sh restart_plus`.

After it starts successfully, enter `localhost:8888` in the browser to open the Dreamview+ interface.

### 2. Start the Required Modules

1. Open `http://localhost:8888` in the browser.

2. Select the `Vehicle Test` mode.

3. Select the corresponding vehicle model according to the actual situation.

4. In the module Controller tab, start the Canbus, Camera, GPS, Localization and Transform modules.

### 3. Check Whether the Channels of Each Module Are Correct

Enter the `cyber_monitor` command in docker and check the following channels.

- Use the `Up/Down arrow keys` to select a channel,

- Use the `Right arrow key` to view the channel details.

| channel_name                            | Item to Check                                               |
| --------------------------------------- | ------------------------------------------------------ |
| `/apollo/localization/pose`             | Make sure data is output normally                                     |
| `/apollo/sensor/gnss/best_pose`         | Make sure data is output normally, and the `sol_type:` option shows `NARROW_INT` |
| `/apollo/sensor/camera/front_6mm/image` | Make sure data is output normally, with a frame rate of about 15 Hz                     |
| `/tf`                                   | Make sure data is output normally                                     |
| `/tf_static`                            | Make sure data is output normally                                     |
| `/apollo/canbus/chassis`                | Make sure data is output normally                                     |
| `/apollo/canbus/chassis_detail`         | Make sure data is output normally                                     |

Use `cyber_monitor` to check whether `/apollo/perception/obstacles` is output normally, and view the obstacle information on DreamView+:

![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_571cf77.png)

The data of `/apollo/perception/obstacles` is shown in the figure below:

![camera_demonstration_perception_obstacle1](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/02d441b2c1aed3836f1a84b88ccd898b.png)

Make sure obstacles can be seen on Dreamview+ and `/apollo/perception/obstacles` contains obstacle information.

### 6. Start the Planning, Prediction and Control Modules

Start the Planning, Prediction and Control modules in `Modules`.

### 7. Verify That the Planning, Prediction and Control Modules Started Successfully

1. In the vehicle visualization panel, click Routing Editing and select the start point and waypoints.

2. Click **Save Editing**.

   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_e405fb7.png)

3. Click the **Send Routing** button.

   In DreamView+, a blue line and a red stop sign appear, as shown in the figure below:

   When there is a person or bicycle (with a rider) in front of the vehicle, view the Planning trajectory line in the Tasks tab, as shown in the figure below:

   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_e4472a9.png)

   Enter the command `cyber_monitor` in the docker environment and view the Planning channel information:

   ![camera_demonstration_planning_data](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/37aad4eb3d789c3ff843fa437a9157a8.png)

   If the trajectory line and topic information shown in the figure above appear, the planning module adaptation and open-loop test have passed; otherwise continue to check the log information for debugging.

### 8. Start Autonomous Driving

With no people or vehicles nearby, hand over authority with the remote controller and click **Autonomous Driving** to put the vehicle into autonomous driving state. While the vehicle drives autonomously, be ready to take over with the remote controller at any time to ensure safety.

## FAQ

### The wheels swing back and forth during autonomous driving (snaking)

This is generally because the vehicle dynamics calibration was not done well; it is recommended to redo the dynamics calibration.

### Lane changes, stopping and other behaviors are not ideal

With stable perception and localization guaranteed, you can try modifying the relevant parameters in the planning configuration file to adjust them. For details, see [Closed-Campus Autonomous Driving Setup -- Planning Adaptation](../应用实践/车辆集成教程/基于激光雷达的封闭园区自动驾驶搭建/规划适配.md).
