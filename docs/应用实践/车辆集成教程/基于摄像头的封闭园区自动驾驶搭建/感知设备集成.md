This user manual aims to help users complete the installation, integration and data verification of the camera perception device (Camera).

## Prerequisites

Complete [Record-and-Replay Setup -- Vehicle Record-and-Replay Demonstration](../应用实践/车辆集成教程/循迹搭建/车辆循迹演示.md).

## Perception Device Integration

### 1. Install and Fix the Camera

The camera should be mounted level, with a downward pitch of 0-2 degrees (tilted down by less than 2 degrees, never tilted up), a roll error of ±1 degree (how level the left and right sides are) and a heading error of ±2 degrees. Keep the lens clean so that image acquisition is not affected.

### 2. Configure the Camera Rules File

The purpose of the camera rules file is that, when Linux boots, the corresponding symbolic link files are generated automatically according to the rules set in the rules file.

1. Outside the docker environment, run the following command to create and edit the camera rules file:
   
   ```
   sudo vim /etc/udev/rules.d/99-webcam.rules
   ```

2. Modify the rules file according to your own setup. An example camera rules file is shown below (it contains the rules of only 2 cameras; if you need 3 cameras, add the third following the same format):
   
   ```
   SUBSYSTEM=="video4linux", SUBSYSTEMS=="pci", ATTR{name}=="FPD1-0100", ATTR{index}=="0", MODE="0666", SYMLINK+="camera/front_6mm", OWNER="apollo", GROUP="apollo"
   SUBSYSTEM=="video4linux", SUBSYSTEMS=="pci", ATTR{name}=="FPD3-0300", ATTR{index}=="0", MODE="0666", SYMLINK+="camera/front_12mm", OWNER="apollo", GROUP="apollo"
   ```
   
   Please modify the `ATTR{name}` values in the rules file according to the actual situation.

3. View the USB attribute information of the connected cameras. Run the following command outside the docker environment:
   
   ```
   udevadm info --attribute-walk --name=/dev/video*
   ```

4. Outside the docker environment, run the following commands to make the configured rules file take effect on the local system:
   
   ```
   bash ~/apollo/docker/setup_host/setup_host.sh
   sudo reboot  // Reboot the industrial PC
   ```

### 3. Start the Camera

#### 1. Check whether the camera is recognized by the system.

With the camera properly connected to the industrial PC, run the `ls /dev/video*` command to check whether the camera is recognized.

- If the camera device has been recognized, device names starting with `video` are displayed.

- If the camera device is not recognized, check whether the cable between the camera and the industrial PC is reliable.

#### 2. Check whether the camera symbolic link files exist.

Check whether the `/dev/camera` directory exists, and whether the two symbolic link files `front_6mm` and `front_12mm` exist in that directory.

> Note: Depending on the rules file configuration, there may be 1 or more symbolic link files.

If the `ls /dev/video*` command shows the camera device but there are no symbolic link files or no `camera` folder, refer to the `Configuring the camera rules file` section above to check whether the rules file is configured correctly.

#### 3. Build the project and start Dreamview+.

##### a. Start the Apollo Docker environment

If you are using package management, follow these steps:

1. Open a command-line terminal and change the path to Apollo:
   
   ```bash
   cd ~/apollo
   ```

2. Enter the following commands to enter the Apollo Docker environment:
   
   ```bash
   aem start # create the container
   aem enter # enter the container
   buildtool build
   ```
   
   > Note: Use `buildtool build` the first time you enter the container; if you only want to build the updated modules, use the following command `buildtool build -p module_name`.
   
   If your terminal looks like the one below, you have successfully entered Apollo's runtime container:
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_7e7a575.png)

If you are using source code, follow these steps to enter the docker environment:

1. Open a command-line terminal and change the path to Apollo:
   
   ```bash
   cd ~/apollo     # change the path to apollo; note there is a space between cd and ~/apollo
   ```

2. Enter the following command to start the Apollo Docker environment:
   
   ```bash
   bash docker/scripts/dev_start.sh
   ```
   
   Start the docker environment:
   
   ```bash
   bash docker/scripts/dev_into.sh
   ```
   
   If your terminal looks like the one below, you have successfully entered Apollo's runtime container:
   
   ```bash
   [user@in-runtime-docker:/apollo]$
   ```

##### b. Start and open Dreamview+

You can start Dreamview+ through package management or from source. Choose one method and start Dreamview+ with the corresponding commands.

- Method 1: Package Management
  
  Enter the docker environment through package management, and run the following command in the docker environment to start Dreamview+:
  
  ```bash
  aem bootstrap start --plus
  ```
  
  > Note:
  > 
  > - If you want to stop Dreamview+, enter `aem bootstrap stop --plus`,
  > - If you want to restart Dreamview+, enter `aem bootstrap restart --plus`.

- Method 2: Source Code
  
  Enter the docker environment from source, and run the following command in the docker environment to start Dreamview+:
  
  ```bash
  bash scripts/bootstrap.sh start_plus
  ```
  
  > Note:
  > 
  > - If you want to stop Dreamview+, enter `bash scripts/bootstrap.sh stop_plus`,
  > - If you want to restart Dreamview+, enter `bash scripts/bootstrap.sh restart_plus`.

After it starts successfully, enter `localhost:8888` in the browser to open the Dreamview+ interface.

#### 4. Start the Camera module.

#### 5. Verify that the Camera is working properly.

If everything is normal, the image captured by the camera appears in the lower right corner of `DreamView`.

Use the `cyber_monitor` tool inside the `docker` environment to check whether `/apollo/sensor/camera/front_6mm/image` and `/apollo/sensor/camera/front_12mm/image` have data output, and whether the frame rate is stable at around 15 frames.

```bash
//Enter the following command to start cyber_monitor
budaoshi@in_dev_docker:/apollo$ cyber_monitor
```

## FAQ

### The symbolic links are not shown after the rules file is modified

After the rules file is modified, the computing unit (HW 3.0) must be restarted for it to take effect.
