This user manual aims to help users complete the camera perception adaptation and enable Camera perception.

## Prerequisites

1. Complete [Record-and-Replay Setup -- Vehicle Record-and-Replay Demonstration](../应用实践/车辆集成教程/循迹搭建/车辆循迹演示.md).

2. Complete [Camera-Based Closed-Campus Autonomous Driving Setup -- Perception Device Integration](../应用实践/车辆集成教程/基于摄像头的封闭园区自动驾驶搭建/感知设备集成.md).

3. Complete [Camera-Based Closed-Campus Autonomous Driving Setup -- Perception Device Calibration](../应用实践/车辆集成教程/基于摄像头的封闭园区自动驾驶搭建/感知设备标定.md).

## Step 2: Start the Camera Module

Drive the vehicle outdoors, control it manually, and check whether perception has data.

### 1. Build the Project and Start Dreamview+

#### 1) Start the Apollo Docker Environment

If you are using package management, follow these steps:

1. Open a command-line terminal and change the path to Apollo:
   
   ```bash
   cd ~/apollo
   ```

2. Enter the following commands to enter the Apollo Docker environment:
   
   ```bash
   aem start # create the container
   aem enter # enter the container
   buildtool build
   ```
   
   > Note: Use `buildtool build` the first time you enter the container; if you only want to build the updated modules, use the following command `buildtool build -p module_name`.
   
   If your terminal looks like the one below, you have successfully entered Apollo's runtime container:
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_7e7a575.png)

If you are using source code, follow these steps to enter the docker environment:

1. Open a command-line terminal and change the path to Apollo:
   
   ```bash
   cd ~/apollo     # change the path to apollo; note there is a space between cd and ~/apollo
   ```

2. Enter the following command to start the Apollo Docker environment:
   
   ```bash
   bash docker/scripts/dev_start.sh
   ```
   
   Start the docker environment:
   
   ```bash
   bash docker/scripts/dev_into.sh
   ```
   
   If your terminal looks like the one below, you have successfully entered Apollo's runtime container:
   
   ```bash
   [user@in-runtime-docker:/apollo]$
   ```

#### 2) Start and Open Dreamview+

You can start Dreamview+ through package management or from source. Choose one method and start Dreamview+ with the corresponding commands.

- Method 1: Package Management
  
  Enter the docker environment through package management, and run the following command in the docker environment to start Dreamview+:
  
  ```bash
  aem bootstrap start --plus
  ```
  
  > Note:
  > 
  > - If you want to stop Dreamview+, enter `aem bootstrap stop --plus`,
  > - If you want to restart Dreamview+, enter `aem bootstrap restart --plus`.

- Method 2: Source Code
  
  Enter the docker environment from source, and run the following command in the docker environment to start Dreamview+:
  
  ```bash
  bash scripts/bootstrap.sh start_plus
  ```
  
  > Note:
  > 
  > - If you want to stop Dreamview+, enter `bash scripts/bootstrap.sh stop_plus`,
  > - If you want to restart Dreamview+, enter `bash scripts/bootstrap.sh restart_plus`.

After it starts successfully, enter `localhost:8888` in the browser to open the Dreamview+ interface.

### 2. Start the Required Modules

1. Open `http://localhost:8888` in the browser.

2. Select the mode according to the actual situation.

3. Select the vehicle model according to the actual situation, and select the corresponding HD map.

4. In Modules, start the Canbus, Camera, GPS, Localization and Transform modules.

### 3. Check Whether the Channels of Each Module Are Correct

Enter the `cyber_monitor` command in docker and check the following channels:

- Use the `Up/Down arrow keys` to select a channel,

- Use the `Right arrow key` to view the channel details.

For more detailed usage of cyber_monitor, see [CyberRT_Developer_Tools](Apollo_Doc_CN_6_0/上机使用教程/实时通信框架CyberRT的使用/CyberRT介绍.md).

| channel_name                             | Item to Check                                      |
| ---------------------------------------- | ----------------------------------------- |
| `/apollo/localization/pose`              | Make sure data is output normally                                 |
| `/apollo/sensor/gnss/best_pose`          | Make sure data is output normally, and the `sol_type:` option shows `NARROW_INT` |
| `/apollo/sensor/camera/front_6mm/image`  | Make sure data is output normally, with a stable frame rate of about 15 Hz                     |
| `/apollo/sensor/camera/front_12mm/image` | Make sure data is output normally, with a stable frame rate of about 15 Hz                     |
| `/tf`                                    | Make sure data is output normally                                 |
| `/tf_static`                             | Make sure data is output normally                                 |
| `/apollo/canbus/chassis`                 | Make sure data is output normally                                 |
| `/apollo/canbus/chassis_detail`          | Make sure data is output normally                                 |

Use `cyber_monitor` to check whether `/apollo/perception/obstacles` is output normally, and view the obstacle information on DreamView+:

## FAQ

### The perception output frame rate does not reach 10 frames

It is recommended to build the Apollo project with `bash apollo.sh build_opt_gpu`.

### The positions of perceived obstacles have a large error compared with the actual obstacles

- Confirm the localization signal status, and make sure the `sol_type` option in `/apollo/sensor/gnss/best_pose` shows `NARROW_INT`.
- Make sure the extrinsic files of all sensors are accurate.
