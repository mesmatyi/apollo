This document describes the configuration of the apollo localization module when adapting apollo on the Lincoln MKZ. The strapdown inertial navigation device PP7 was integrated in hardware earlier and the PP7 device has been configured. This document configures the apollo localization module accordingly.

## Prerequisites

- Completed [Record-and-Replay Setup -- Vehicle Integration](../应用实践/车辆集成教程/循迹搭建/车辆集成.md).

- Completed [Record-and-Replay Setup -- Strapdown Inertial Navigation Device PP7 Configuration](../应用实践/车辆集成教程/循迹搭建/惯导设备PP7配置.md).

- You have an RTK base station account.

## apollo Localization Module Configuration: System File Configuration

The system file configuration mainly has two parts: the `gnss_conf.pb.txt` file configuration and the `localization.conf` file configuration.

| File Name              | File Location                                                              | Description       |
| ----------------- | ----------------------------------------------------------------- | -------- |
| gnss_conf.pb.txt  | modules/calibration/data/车型目录/gnss_conf/gnss_conf.pb.txt          | gnss configuration file |
| localization.conf | modules/calibration/data/车型目录/localization_conf/localization.conf | Localization module configuration file |

### gnss_conf.pb.txt File Configuration

The content of the `gnss_conf.pb.txt` file is shown below. You only need to fill the IP address, port number, mount point, user name and password of your own base station into the corresponding ntrip items of rtk_from; no other content needs to be changed.

> Note: If you changed the IP address and port number of the PP7 device in [Record-and-Replay Setup -- Strapdown Inertial Navigation Device PP7 Configuration](../应用实践/车辆集成教程/循迹搭建/捷联惯性导航设备PP7配置.md), the `address` and `port` values of the `tcp` items of the `data` module and the `rtk_to` module in `gnss_conf.pb.txt` must be changed accordingly.

```bash
data {
    format: NOVATEL_BINARY
    tcp {
        address: "192.168.10.4"
        port: 2000
    }
}

rtk_from {
    format: RTCM_V3
    ntrip {
        address: "<IP>"
        port: <PORT>
        mount_point: "<MOUNTPOINT>"
        user: "<USER>"
        password: "<PASSWORD>"
        timeout_s: 5
    }
    push_location: true
}

rtk_to {
    format: NOVATEL_BINARY
    tcp {
        address: "192.168.10.4"
        port: 3000
    }
}

rtk_solution_type: RTK_RECEIVER_SOLUTION
imu_type: G320N
proj4_text: "+proj=utm +zone=50 +ellps=WGS84 +towgs84=0,0,0,0,0,0,0 +units=m +no_defs"

tf {
    frame_id: "world"
    child_frame_id: "novatel"
    enable: false
}

# If given, the driver will send velocity info into novatel one time per second
wheel_parameters: "SETWHEELPARAMETERS 100 1 1\r\n"

gpsbin_folder: "/apollo/data/gpsbin"

#########################################################################
# notice: only for debug, won't configure device through driver online!!!
#########################################################################
login_commands: "UNLOGALL THISPORT\r\n"
login_commands: "LOG COM2 GPRMC ONTIME 1.0 0.25\r\n"
login_commands: "EVENTOUTCONTROL MARK2 ENABLE POSITIVE 999999990 10\r\n"
login_commands: "EVENTOUTCONTROL MARK1 ENABLE POSITIVE 500000000 500000000\r\n"
login_commands: "LOG GPGGA ONTIME 1.0\r\n"

login_commands: "log bestgnssposb ontime 1\r\n"
login_commands: "log bestgnssvelb ontime 1\r\n"
login_commands: "log bestposb ontime 1\r\n"
login_commands: "log INSPVAXB ontime 0.5\r\n"
login_commands: "log INSPVASB ontime 0.01\r\n"
login_commands: "log CORRIMUDATASB ontime 0.01\r\n"
login_commands: "log RAWIMUSXB onnew 0 0\r\n"
login_commands: "log INSCOVSB ontime 1\r\n"
login_commands: "log mark1pvab onnew\r\n"
login_commands: "log rangecmpb ontime 0.2\r\n"
login_commands: "log rangecmpb_1 ontime 0.2\r\n"

login_commands: "log rangeb ontime 0.2\r\n"
login_commands: "log bdsephemerisb\r\n"
login_commands: "log gpsephemb\r\n"
login_commands: "log gloephemerisb\r\n"
login_commands: "log bdsephemerisb ontime 15\r\n"
login_commands: "log gpsephemb ontime 15\r\n"
login_commands: "log gloephemerisb ontime 15\r\n"

login_commands: "log imutoantoffsetsb once\r\n"
login_commands: "log vehiclebodyrotationb onchanged\r\n"
login_commands: "log headingb onchanged\r\n"

logout_commands: "EVENTOUTCONTROL MARK2 DISABLE\r\n"
logout_commands: "EVENTOUTCONTROL MARK1 DISABLE\r\n"
```

### Localization.conf File Configuration

For the configuration of the `localization.conf` file, you only need to change the values of the corresponding items in `localization.conf` according to the actual installation of your PP7.

Open the `localization.conf` file, find the corresponding items and modify them according to your actual situation. See the table below for the specific items to modify:

> Note: If this configuration file is not configured correctly, subsequent functions such as sensor calibration and virtual lane line creation may be affected.

| Parameter                               | Description                                                                                                                                                |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| lidar_height_default             | Change the value to the distance from the lidar center to the ground. Unit: m                                                                                                                        |
| local_utm_zone_id                | The user needs to look up the utm_zone of their region and modify it. For example, the utm_zone of the Beijing area is 50. For looking up the utm_zone, see [UTM zone](https://mangomap.com/robertyoung/maps/69585/what-utm-zone-am-i-in-#). |
| imu_to_ant_offset_x              | Lever arm value along the x axis. Unit: m. For how to measure the lever arm value, see `Record-and-Replay Setup -- Vehicle Integration`.                                                                                                             |
| imu_to_ant_offset_y              | Lever arm value along the y axis. Unit: m. For how to measure the lever arm value, see `Record-and-Replay Setup -- Vehicle Integration`.                                                                                                             |
| imu_to_ant_offset_z              | Lever arm value along the z axis. Unit: m. For how to measure the lever arm value, see `Record-and-Replay Setup -- Vehicle Integration`.                                                                                                             |
| --enable_lidar_localization=true | Change to `--enable_lidar_localization=false`                                                                                                           |

## Check Whether the Localization Module Can Start Normally

Move the vehicle to a flat, open area outdoors and perform the following operations in order.

### 1. Build the Project and Start Dreamview+

You can start and open Dreamview+ using package management or source code:

#### 1) Start the Apollo Docker Environment

- If you are using package management, follow these steps:
  
  1. Open a command-line terminal and change the path to Apollo:
     
     ```bash
     cd ~/apollo
     ```
  
  2. Enter the following commands to enter the Apollo Docker environment:
     
     ```bash
     aem start # create the container
     aem enter # enter the container
     buildtool build
     ```

> Note: Use `buildtool build` the first time you enter the container; if you only want to build the updated modules, use the following command `buildtool build -p module_name`.

     If your terminal looks like the one below, you have successfully entered Apollo's runtime container:
    
     ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_7e7a575.png)

- If you are using source code, follow these steps to enter the docker environment:
  
  1. Open a command-line terminal and change the path to Apollo:
     
     ```bash
     cd ~/apollo     # change the path to apollo; note there is a space between cd and ~/apollo
     ```
  
  2. Enter the following command to start the Apollo Docker environment:
     
     ```bash
     bash docker/scripts/dev_start.sh
     ```
     
     Start the docker environment:
     
     ```bash
     bash docker/scripts/dev_into.sh
     ```
     
     If your terminal looks like the one below, you have successfully entered Apollo's runtime container:
     
     ```bash
     [user@in-runtime-docker:/apollo]$
     ```

#### 2) Start and Open Dreamview+

You can start Dreamview+ through package management or from source. Choose one method and start Dreamview+ with the corresponding commands.

- Method 1: Package Management
  
  Enter the docker environment through package management, and run the following command in the docker environment to start Dreamview+:
  
  ```bash
  aem bootstrap start --plus
  ```

> Note:
> 
> - If you want to stop Dreamview+, enter `aem bootstrap stop --plus`,
> - If you want to restart Dreamview+, enter `aem bootstrap restart --plus`.

- Method 2: Source Code
  
  Enter the docker environment from source, and run the following command in the docker environment to start Dreamview+:
  
  ```bash
  bash scripts/bootstrap.sh start_plus
  ```

> Note:
> 
> - If you want to stop Dreamview+, enter `bash scripts/bootstrap.sh stop_plus`,
> - If you want to restart Dreamview+, enter `bash scripts/bootstrap.sh restart_plus`.

After it starts successfully, enter `localhost8888` in the browser to open the Dreamview+ interface.

### 2. Start the Localization Module

1. Open `(http://localhost:8888)` in the browser.

2. Select the `Vehicle Test` mode.

3. In the Module Controller tab, start the GPS and Localization modules.

### 3. Check the GPS Signal

Follow the steps below to check the GPS signal:

1. Open a new command-line terminal and enter and run the command `bash docker/scripts/dev_into.sh` to enter the apollo docker environment.

2. In the new terminal, enter and run the `cyber_monitor` command. In the listed channel information, use the keyboard Up/Down arrow keys together with the page keys to select the `/apollo/sensor/gnss/best_pose` channel, press the keyboard Right arrow key to enter the `/apollo/sensor/gnss/best_pose` channel, and check whether the value of the `sol_type` field of this channel is `NARROW_INT`.
   
   - If it is NARROW_INT, the GPS signal is good;
   
   - If it is not NARROW_INT, move the vehicle to an unobstructed position and look again, until NARROW_INT appears.
   
   ![localization_config_check_gps_1](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/03c04075948cfb49a9e225fffad1f5d9.png)
   ![localization_config_check_gps_2](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/c7d30987fd4a5fb38980b126ef66fc2e.png)

3. Enter the `/apollo/sensor/gnss/imu` channel in the same way (press the keyboard Left arrow key to exit a channel) and confirm that the IMU data is refreshing. If it refreshes, the GPS module has been configured successfully.

### 4. Check the Localization Signal

Likewise use the `cyber_monotor` tool, enter the `/apollo/localization/pose` channel and check whether data is refreshing. If not, wait a few minutes until data refreshes. If data refreshes, the localization module has been configured successfully.

![localization_config_check_pose_1](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/15a7f3c8184fa8b24fd51de6632a5a0f.png)
![localization_config_check_pose_2](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/4c3f0947c873c54f469d69d10e8b562c.png)
