Vehicle cloud calibration collects the vehicle chassis throttle pedal amount, brake pedal amount, vehicle speed and acceleration as the input of the vehicle longitudinal dynamics model, and uses machine learning to generate the pedal calibration table of the corresponding vehicle. The generated calibration table has a large data volume and high precision, improving the vehicle's control accuracy. The vehicle pedal calibration system mainly consists of four parts:

- Collect calibration data in the `DreamView` data collection monitor;

- Preprocess the data locally;

- Upload the calibration data to the BOS cloud drive and submit the calibration task;

- Generate visualized calibration results for performance evaluation.

## Step 1. Modify the Configuration File

Before starting calibration, configure the data collection for vehicle pedal calibration according to the actual vehicle's maximum speed and throttle and brake pedal limits, so as to adapt to the vehicle's calibration and make the calibration data cover the effective range of the vehicle's pedals as much as possible. We have set the default vehicle calibration data collection configuration file of the development kit in the file `apollo/modules/calibration/data/$vehicle_type/dreamview_conf/data_collection_table.pb.txt`. The configuration file location differs for different vehicle models, mainly determined by the vehicle model parameter `$vehicle_type`; select the corresponding vehicle model according to the vehicle nameplate information.

The following uses MKZ vehicle calibration as an example. The MKZ vehicle calibration configuration file is in `apollo/master/modules/dreamview/conf/data_collection_table.pb.txt`.

After you understand the composition of the calibration file, you can modify the required data collection configuration file yourself if necessary. Normally, the default calibration configuration covers most of the cart's pedal control range. **It is recommended that you do not need to modify this configuration file separately and simply use the default calibration configuration**. The calibration conditions of the cart mainly designed in the default calibration configuration file are as follows:

Vehicle forward model

- Speed conditions

  - Low speed 0 ~ 10 m/s

  - Medium speed 10 ~ 20 m/s

  - High speed >= 20 m/s

- Throttle conditions

  - Small throttle Throttle deadzone ~ 25%

  - Medium throttle 25% ~ 30%

  - Large throttle Throttle >= 30%

- Brake conditions

  - Small brake Brake deadzone ~ 20%

  - Medium brake 20% ~ 25%

  - Hard brake Brake >= 25%

The `Throttle deadzone` above is the ineffective section of the vehicle throttle pedal that produces no acceleration, **and developers can modify this parameter according to the actual vehicle**; the `Brake deadzone` is the ineffective section of the vehicle brake pedal that produces no deceleration, generally set at a low pedal opening, **and developers can modify this parameter according to the actual vehicle**. These parameters are set in `throttle_deadzone` and `brake_deadzone` in the file `apollo/modules/common/data/vehicle_param.pb.txt`. They must be determined before calibration starts, and the configuration file uploaded for data training later must also use these parameters correspondingly.

According to the above calibration conditions, all the calibration conditions of the vehicle can be matched, 12 conditions in total:

- Low speed, small throttle

- Low speed, medium throttle

- Low speed, large throttle

- High speed, small throttle

- High speed, medium throttle

- High speed, large throttle

- Low speed, small brake

- Low speed, medium brake

- Low speed, hard brake

- High speed, small brake

- High speed, medium brake

- High speed, hard brake

After confirming the above calibration conditions, normally the default calibration configuration covers most of the cart's pedal control range. If you need to modify the configuration file, modify the `Go Straight` part of the configuration in `apollo/master/modules/dreamview/conf/data_collection_table.pb.txt`; the other parts of the configuration code do not need to be modified or deleted. The configuration takes effect after starting `DreamView` and reselecting the vehicle. The specific code changes are as follows:

## Step 2. Collect Calibration Data

### 1. Preparation

After finishing the configuration file changes, move the vehicle to a site suitable for calibration, start Apollo, and run the following commands:

```
  bash apollo.sh build_opt_gpu  # rebuild so that the configuration changes take effect
  bash scripts/bootstrap.sh
```

1. Open `DreamView (http://localhost:8888)` in the browser.

2. In `--setup mode--`, select the `vehicle calibration` mode.

3. In `--vehicle--`, select the corresponding vehicle model.

   ![vehicle_calibration_select_vehicle](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/9b80be81f6e7be44b3519ccce85f2b37.png)

4. Start the software modules required for calibration.

Before calibration, data containing the vehicle chassis and localization information must be collected as input. You can start the related module software through the module switches on the `DreamView` interface. Select the `Module Controller` tab in the left sidebar of the `DreamView` interface, then start the `Canbus`, `GPS` and `Localization` modules in the main interface.

![vehicle_calibration_launch_modules](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/bef51bb802c20745fd48cf0af1bd5548.png)

Check the status of `Canbus`, `GPS` and `RTK` through `Components` on the left, and proceed to the next step only when all signals reach `OK`. After `Localization` starts, wait 1 to 2 minutes for the `RTK` status to become OK.

| channel_name                    | Item to Check                                                 |
| ------------------------------- | -------------------------------------------------------- |
| `/apollo/canbus/chassis`        | Make sure data is output normally                                       |
| `/apollo/canbus/chassis_detail` | Make sure data is output normally                                       |
| `/apollo/sensor/gnss/best_pose` | Make sure data is output normally, and the `sol_type:` option shows `NARROW_INT` |
| `/apollo/localization/pose`     | Make sure data is output normally                                       |

![vehicle_calibration_check_components.png](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/af6f24204344cd3dcd87a5fffde976e8.png)

5. Enter the collection interface.

After confirming that the software modules started in the previous step are in `OK` status, click the `Tasks` tab in the left sidebar of the `DreamView` interface, turn on the `Fuel Client` switch in the `Others` area to start the cloud service collection interface, and then select the `Go Straight` tab on the upper right of the interface to view it.

![vehicle_calibration_fuel_cleint](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/a98d5c5f541117c2de2e2ff6af2999c9.png)

### 2. Start Collecting

On the `DreamView` interface, click the left sidebar, select `Module Controller`, and click the `Recorder` switch; the Apollo system starts recording the vehicle calibration data.

> Note:
>
> - **You must turn on the `Recorder` switch first** and then collect the calibration data. In practice, data is often not recorded and saved because the `Recorder` switch was not turned on, which hurts efficiency.
> - If the progress bars of the data collector on the right have already increased somewhat before you turn on the Recorder switch, that is fine, because the collected amounts on the progress bars are cleared and recording restarts after the `Recorder` switch is turned on.
> - When recording data, it is recommended that after turning on the `Recorder` switch for the first time, you collect all the calibration case data in one go and only then turn off the `Recorder` switch. A calibration data collection usually takes 20-40 minutes, depending on proficiency, site size and so on.

![vehicle_calibration_launch_recorder.png](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/8f16dae658a08817efcd071a59f26457.png)

Now drive the vehicle manually and, following the data collection monitor on the right of `Dreamview`, collect vehicle data for the corresponding calibration conditions. Each time a calibration condition is met, the progress bar increases a little, until the progress bar is full.

![vehicle_calibration_collect_data](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/7d3adf5f4d33e011f9f65005b09ce616.png)

When all the calibration condition progress bars (**blue**) in the monitor have been fully collected, click to turn off `Recorder`, stop the data recording, and end the vehicle calibration data collection.

> Note: In principle it is best for generating the calibration result if all the progress bars are fully collected, but you can also collect the progress bars according to the actual situation, depending on the site size limits, speed limits and so on. For example, some cases are easy to fill and some are very hard; for data that is hard to collect, collecting 60-80% is also acceptable.

![vehicle_calibration_collect_data_complete](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/3590119e3968570e58e1a5ce7509c124.png)

## Step 3. Submit the Calibration Task

### 1. Upload the Preprocessed Data to BOS

Before uploading data, note the following:

1. Preprocess the calibration data.

After collecting the vehicle's calibration data and turning off `Recorder`, click the `"Preprocess"` button in the lower right corner to preprocess the calibration data.

![vehicle_calibration_preprocess_data.png](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/5c72c0466b6ea1846684cbde16447b0d.png)

2. View the preprocessing result.

After clicking the `"Preprocess"` button, a data integrity check (sanity check) is first performed on the calibration data. If the check fails, an error message is shown below the progress bar (normally, if you follow the steps in this document one by one, the integrity check will not fail).

The preprocess button only needs to be clicked once, not multiple times.

![vehicle_calibration_preprocess_data_complete](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/30dd95f801d42f3997784a0b6f008b9f.png)

3. The generated results are in the following directory.

After the data integrity check ends, you are prompted that the generated preprocessed data is stored in `apollo/output/task-*******`. The folder is named after the time of processing, so developers just need to look in the `apollo/output` directory for the most recent task folder.

As shown in the figure below, copy the preprocessed folder `task-2021-01-04-18-12` for use in calibration.

![vehicle_calibration_preprocess_data_folder](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/c9f50aa54485e5b6bf93489c44f1ea68.png)

4. Upload the generated result to BOS.

In the initial directory of [BOS](https://gitee.com/ApolloAuto/apollo/blob/master/docs/Apollo_Fuel/apply_bos_account_cn.md), upload the folder `task-2021-01-04-18-12` selected in the previous step.

![vehicle_calibration_upload_bos](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/bf7cc850cd2d96c34962b3350f9042dc.png)

### 2. Submit the Calibration Task

1. Log in to the [Apollo cloud service task page](http://bce.apollo.auto/login) and choose to log in with a Baidu account.

2. In the left box, select `Apollo Fuel-->Tasks`.

![vehicle_calibration_submit_task1](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/97df047367ecdf747c33e5073a0004c1.jpg)

3. Click `New Task`.

![vehicle_calibration_submit_task2](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/ba59ee2eef38225a1fd9c76bd4a00e89.jpg)

4. In the drop-down box, select `Vehicle Calibration`.

![vehicle_calibration_submit_task3](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/8aa0046dee27a723daed9bca65070131.png)

5. Enter the corresponding data path to be evaluated. In `Input Data Path`, fill in the root directory; in this example it is `task-2021-01-04-18-12` (because "task-2021-01-04-18-12" is in the root directory of BOS).

![vehicle_calibration_submit_task4](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/dce25652491f7e50df6bbc5013e3b13a.png)

### 3. Obtain the Calibration Result and the Calibration Table

After the cloud calibration task completes, you will receive a calibration result email in your registered mailbox (please contact the business department). If the calibration task succeeds, it will contain the calibration table and calibration result images.

### 4. Write the Calibration Table into the Control Configuration File

The generated calibration table is named `vehicle_model_calibration_table.pb.txt`. The calibration data in the calibration table is the `calibration_table` field; copy all the data and replace the `calibration_table` section under the corresponding `lon_controller_conf` field in `apollo/modules/control/conf/control_conf.pb.txt`.

The following is an example snippet of the cloud calibration data (the first 4 segments are excerpted):

```text
    calibration {
      speed: 0.0
      acceleration: -1.3040223121643066
      command: -69.0
    }
    calibration {
      speed: 0.0
      acceleration: -1.2989914417266846
      command: -65.63157894736842
    }
    calibration {
      speed: 0.0
      acceleration: -1.2903447151184082
      command: -62.26315789473684
    }
    calibration {
      speed: 0.0
      acceleration: -1.2760969400405884
      command: -58.89473684210526
    }
```

## FAQ

### While calibrating the vehicle, I received the following error email: the data integrity check failed

![vehicle_calibration_online_error1](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/5865b79d3ac0a861a556b4650a9bc50a.png)

Troubleshooting method:

1. Check whether the `folder structure` is correct.

Generally, the folder directory is generated automatically during data preprocessing. If the folder directory has errors, you can modify it manually by referring to the directory in the figure below.

All the collected calibration data is saved in the `apollo/data/bag/` directory. Find the folders named `year-month-day-hour-minute-second` and locate the data belonging to the vehicle calibration collection by time. We can collect data in batches, that is, collect part of the data each time, so the data is recorded in different `year-month-day-hour-minute-second` folders (**Note**: by default, after data collection, 2 folders with similar timestamps are generated under the `apollo/data/bag/` folder, named `year-month-day-hour-minute-second` and `year-month-day-hour-minute-second_s` respectively; developers can ignore the folders with the `_s` suffix and only need to use the calibration data recorded in the `year-month-day-hour-minute-second` folders), or collect everything in one go, so all the data is recorded in the same folder. Collecting the vehicle calibration data for the above calibration conditions usually takes about 20 minutes.

1) The correct folder structure is shown in the figure below:

    ![vehicle_calibration_online_structure](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/7c86f944f1152a3417d54f51e93ca458.png)

2) `Origin Folder` must be the **BOS root directory**; make sure the `task001` directory is created under the BOS root directory (root directory: the directory you first see after logging in to the BOS storage server, generally the `Bucket name` directory).

3) `task001, task002...` represent a vehicle calibration task folder, that is, each time a calibration task is submitted, the vehicle data in one `task folder` is trained; the level above the `task folder` (`Origin Folder`) can be the BOS root directory or another directory.

4) `Vehicle1, Vehicle2...` represent the folders of the calibrated vehicles, which can be named in the form of vehicle name + number according to the actual situation, such as `ch01`, `ch02`. One task folder can contain multiple Vehicle folders, so multiple vehicles can be calibrated in one task submission.

5) Import the collected vehicle calibration data into the `Records` folder; the recorded vehicle data is in the `apollo/data/bag/` directory.

> Note: The `Records` folder needs 2 levels of subfolders: the first level is the date (year-month-day), such as `2019-04-19` in the figure above, and the second level is the specific record folder (year-month-day-hour-minute, etc.), such as `2019-04-19-12-45-01` in the figure above. Be sure to keep the 2-level folder structure under the `Records` folder, otherwise calibration will later fail to find the file data; the folder structure is as shown in the figure above;

6) The `Configuration File` is `vehicle_param.pb.txt` (the vehicle configuration file), located at `apollo/modules/common/data/vehicle_param.pb.txt`. Copy the file `vehicle_param.pb.txt` from this directory into the corresponding vehicle calibration folder in BOS, such as the `Vehicle2` folder in the figure above.

7) Summary of the folder structure above.

    BOS root directory -> Task Folder -> Vehicle Folder -> Records + vehicle_param.pb.txt

2. Check whether the vehicle configuration file (`vehicle_param.pb.txt`) has been added in the vehicle folder.

3. Check whether the recorded data package contains the channel data required for calibration.

   - Via `cyber_recorder info xxxxxx.record.xxxxx`

Check whether the collected data contains data from the following 3 `channel`s:

- `/apollo/canbus/chassis`

- `/apollo/sensor/gnss/best_pose`

- `/apollo/localization/pose`

The figure below shows a correct data package:

![vehicle_calibration_online_record_check](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/8c6a214b2daf7074d5bbad02f3e3dd2c.png)

If any of the above channels is found to be missing, check the related modules.
