The vehicle control evaluation cloud service parses road-test data from autonomous driving and rates the vehicle's control performance, so you can understand how well the vehicle is controlled. Its multi-dimensional scoring results present a comprehensive and objective evaluation of vehicle control.

## Prerequisites

Vehicle control evaluation scores and evaluates control based on the vehicle's autonomous driving data, so the vehicle must have completed closed-loop autonomous driving, either record-and-replay autonomous driving or autonomous driving with perception. Before evaluating vehicle control, please complete the following steps:

1. [Record-and-Replay Setup -- Vehicle Integration](../应用实践/车辆集成教程/循迹搭建/车辆集成.md)

2. [Record-and-Replay Setup -- Localization Module Configuration](../应用实践/车辆集成教程/循迹搭建/定位模块配置.md)

3. [Record-and-Replay Setup -- Apollo System Installation](../应用实践/车辆集成教程/循迹搭建/Apollo系统安装.md)

4. [Record-and-Replay Setup -- Vehicle Record-and-Replay Demonstration](../应用实践/车辆集成教程/循迹搭建/车辆循迹演示.md)

## Step 1: Data Collection

### 1. Data Recording

Complete one or more autonomous drives (record-and-replay / perception closed loop) and record data packages.

### 2. Data Check

> Note: Before uploading data for control evaluation, be sure to check that the data package contains the channels required for evaluation. Otherwise, the data will lack information from the relevant channels and the evaluation will fail.

The data for control evaluation must contain at least the following channel information to be evaluated correctly:

| Module       | channel name                   | Item to check                  |
| ------------ | ------------------------------ | ------------------------------ |
| Canbus       | `/apollo/canbus/chassis`       | Make sure chassis data is output normally |
| Control      | `/apollo/control`              | Make sure control information data is output normally; this data is only available after autonomous driving is started |
| Planning     | `/apollo/planning`             | Make sure planning information is output normally |
| Localization | `/apollo/localization/pose`    | Make sure position data is output normally |
| GPS          | `apollo/sensor/gnss/best_pose` | Make sure `sol_type` is `NARROW_INT` |

Use the `cyber_recorder` command to check whether the collected data contains data for the above `channel`s:

```
 cyber_recorder info xxxxxx.record.xxxxx
```

As shown in the figure below, if the `messages` count of the corresponding `channel` in the table above is not 0, the data is valid.

![profiling_channel_check](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/11311803fa6ed3651f54ee6d722edfa0.png)

## Step 2: Submit a Control Evaluation Cloud Service Task

### 1. Upload the Preprocessed Data to BOS

Before uploading the data, note the following:

1. Folder structure requirements: please arrange the data in the following folder structure:

![profiling_folder_structure](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/0f3e9031b129617c76a0d4717fff88e2.png)

2. `Origin Folder` is generally the **root directory of BOS**. In this example, the `task001` directory is created under the BOS root directory (root directory: the directory you first see after logging in to the BOS storage server, which is generally the `Bucket name` directory);

3. `task001, task002...` represent folders of one evaluation task. Each time an evaluation task is submitted, only the path of one task directory can be entered, and the cloud analyzes and scores the data in that folder. One task folder can contain multiple vehicle folders, so a single submitted task folder can include multiple vehicles. If `task001` is in the BOS root directory, you only need to enter `task001` as the input directory path when submitting the task; if it is in another directory, you need to enter the absolute path starting from the root directory, such as `xxx/task001`.

4. `Vehicle1, Vehicle2...` represent the folders of the vehicles being evaluated. They can be named in the form of vehicle name + number according to the actual situation, such as `vehicle01` and `vehicle02`. Each `Vehicle folder` contains the autonomous driving data folders to be evaluated and the configuration file of that vehicle.

> Note: The autonomous driving data folder must have 2 levels of subfolders, and the record data files are placed in the second-level folders. As shown in the folder structure diagram above, depending on the autonomous driving scenario, it can be divided into `straight` (going straight), `left` (turning left), `right` (turning right), and so on. Each scenario can also be divided by dimensions such as speed, for example `1m/s`, `2m/s`, `3m/s`, and so on. The speed-level folder contains the autonomous driving data under that scenario and speed condition.

5. `Configuration File` is `vehicle_param.pb.txt` (the vehicle configuration file). This file is in the `apollo/modules/calition/data/<vehicle model>` folder. Copy the `vehicle_param.pb.txt` in that folder to the corresponding vehicle control evaluation folder in BOS, for example, into the `Vehicle2` folder in the figure above.

6. Summary of the above folder structure:
   
   BOS root directory -> task folder -> vehicle model folder -> specific autonomous driving data packages + vehicle_param.pb.txt

### 2. Submit the Control Evaluation Task

1. Go to the [Apollo Cloud Service task page](http://bce.apollo.auto/login) and choose to log in with a Baidu account.

2. In the left panel, select `Apollo Fuel-->Tasks`.

![profiling_submit_task1](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/97df047367ecdf747c33e5073a0004c1.jpg)

3. Click `New Task`.
   
   ![profiling_submit_task2](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/ba59ee2eef38225a1fd9c76bd4a00e89.jpg)

4. In the drop-down box, select `Control Evaluation`.

![profiling_submit_task3](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/11c85b41c270a48123fb06bd824e9687.png)

5. Enter the path of the data to be evaluated. In `Input Data Path`, fill in the path up to the root directory; in this example, enter `task001`.

![profiling_submit_task4](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/9193a5f53d20bc1d0e849491a9d9501b.png)

### 3. Obtain the Evaluation Results

After the evaluation task is completed, you will receive 2 result emails at the registered email address (confirmed with business contacts): the control grading results (Grading results) and the data chart display email (Visualization results).

- Grading results email
  
  ![profiling_grading_results](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/8f8cdd95acd10908886dc6aa48862ddc.png)

The grading email generates results separately for each first-level folder under the `task->vehicle` level; that is, results are generated per category according to `straight` (going straight) and `left` (turning left) in the file structure described above. After downloading the grading results attachment, you can see the specific content of the evaluation attachment, as shown in the figure below:

![profiling_grading_folder](https://bce.bdstatic.com/p3m/Apollo-Homepage-Document/images/Apollo-D-KIT/eb40079d3c36f83ea7ed85e8e642cbdf.png)

Among them, `1mps_Dev_Kit_Lon_Lat_Controller_control_performance_grading.txt` and `2mps_Dev_Kit_Lon_Lat_Controller_control_performance_grading.txt` in each group directory (`1_Dev_Kit_left_gradings` and `2_Dev_Kit_straight_gradings`) are the grading result files, and `1mps_Dev_Kit_Lon_Lat_Controller_control_profiling_conf.pb.txt` and `2mps_Dev_Kit_Lon_Lat_Controller_control_profiling_conf.pb.txt` are the configuration files corresponding to the grading. These files are currently set by default and cannot be modified; they mainly define the evaluation baseline for each grading metric.

Open one of the grading result files, for example `1_Dev_Kit_left_gradings/1mps_Dev_Kit_Lon_Lat_Controller_control_performance_grading.txt`, to see the corresponding evaluation. The evaluation scores are mainly shown as root-mean-square results, displayed as percentages, as shown in the figure below:
