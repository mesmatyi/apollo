This document describes how to implement the record-and-replay function on the development kit. Record-and-replay is the minimal closed-loop subset of autonomous driving: in hardware, the integration of a minimal autonomous driving system must be built, and in software, the configuration, calibration and startup of the related modules must be done, before the record-and-replay operation can be demonstrated. During record-and-replay, it both tests how well developers have mastered the preparation work above and gives a very direct feel for the autonomous driving experience.

## Prerequisites

1. [Record-and-Replay Setup -- Vehicle Integration](../应用实践/车辆集成教程/循迹搭建/车辆集成.md)

2. [Record-and-Replay Setup -- Apollo System Installation](../应用实践/车辆集成教程/循迹搭建/Apollo系统安装.md)

3. [Record-and-Replay Setup -- Localization Module Configuration](../应用实践/车辆集成教程/循迹搭建/定位模块配置.md)

4. [Record-and-Replay Setup -- Vehicle Dynamics Cloud Calibration](Apollo_Beta_Doc/应用实践/车辆集成教程/循迹搭建/车辆动力学云标定.md)

5. Make sure to experiment in relatively safe conditions, such as an open site with few vehicles and people.

6. Make sure at least two people operate: one operates the vehicle as the safety driver and one operates autonomous driving, with the safety driver ready to take over at any time.

## Step 1: Start Up

### 1. Start the Canbus Driver

After starting the industrial PC, open a command-line terminal (Terminal) on the desktop, go to the CAN card directory (by default under the home path), and start the CAN driver:

```bash
bash ~/socketcan/start.sh
```

### 2. Start the Apollo Docker Environment

- If you are using package management, follow these steps:
  
  1. Open a command-line terminal and change the path to Apollo:
     
     ```bash
     cd ~/apollo
     ```
  
  2. Enter the following commands to enter the Apollo Docker environment:
     
     ```bash
     aem start # create the container
     aem enter # enter the container
     buildtool build
     ```

> Note: Use `buildtool build` the first time you enter the container; if you only want to build the updated modules, use the following command `buildtool build -p module_name`.

     If your terminal looks like the one below, you have successfully entered Apollo's runtime container:
    
     ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_7e7a575.png)

- If you are using source code, follow these steps to enter the docker environment:
  
  1. Open a command-line terminal and change the path to Apollo:
     
     ```bash
     cd ~/apollo     # change the path to apollo; note there is a space between cd and ~/apollo
     ```
  
  2. Enter the following command to start the Apollo Docker environment:
     
     ```bash
     bash docker/scripts/dev_start.sh
     ```
     
     Start the docker environment:
     
     ```bash
     bash docker/scripts/dev_into.sh
     ```
     
     If your terminal looks like the one below, you have successfully entered Apollo's runtime container:
     
     ```bash
     [user@in-runtime-docker:/apollo]$
     ```

### 3. Start and Open Dreamview+

You can start Dreamview+ through package management or from source. Choose one method and start Dreamview+ with the corresponding commands.

1. Start Dreamview+
   
   - Method 1: Package Management
     
          Enter the docker environment through package management, and run the following command in the docker environment to start Dreamview+:
         
          ```bash
          aem bootstrap start --plus
          ```

> Note:
> 
> - If you want to stop Dreamview+, enter `aem bootstrap stop --plus`,
> - If you want to restart Dreamview+, enter `aem bootstrap restart --plus`.

    - Method 2: Source Code
    
      Enter the docker environment from source, and run the following command in the docker environment to start Dreamview+:
    
      ```bash
      bash scripts/bootstrap.sh start_plus
      ```

> Note:
> 
> - If you want to stop Dreamview+, enter `bash scripts/bootstrap.sh stop_plus`,
> - If you want to restart Dreamview+, enter `bash scripts/bootstrap.sh restart_plus`.

2. After it starts successfully, enter `localhost8888` in the browser to open the Dreamview+ interface.

## Step 2: Record the Trajectory

### 1. Select the Record-and-Replay Mode

1. In **Mode Settings** > **Mode**, select the **Vehicle Test** mode.

2. In **Operations**, select the **Waypoint_Follow** (record-and-replay) operation.

### 2. Start the Modules Required for Record-and-Replay Driving

1. In **Modules**, start the **Canbus**, **Control**, **ExternalCmd**, **GPS**, **Localization** and **Transform** buttons.
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_d7d75b6.png)

> Note: ExternalCmd is a child process of planning, and record-and-replay uses this child process; in road-test mode, you only need to turn on the planning module.

### 3. Check the Connection Status

1. Check the Component status.
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_69f58c5.png)

> Note:
> 
> - Green OK in Component is normal, and you can proceed with the operations below.
> - A yellow WARNING only means the signal is poor and the module has started; as long as it is not ERROR, it does not affect record-and-replay.

Turn on cyber_monitor and view the channel information.

2. View the cyber_monitor data.
   
   Enter the docker environment and enter `cyber_monitor`. In the cyber_monitor tool that starts, you can see a lot of channel information, among which /tf and /tf_static correspond to the Transform module, /apollo/localization/pose corresponds to the Localization module, and apollo/sensor/gnss/best_pose corresponds to the GPS module.
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_4650e42.png)
   
   Use the Up/Down arrow keys to select the channel /apollo/sensor/gnss/best_pose and press the Right arrow key to enter this channel, and check whether the sol_type item is NARROW_INT. If it is NARROW_INT, the GPS signal is good and meets the localization requirements; if it is not NARROW_INT, move the vehicle with the remote controller until NARROW_INT appears.
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_f716d6d.png)
   
   After checking that all the started modules are normal, you can proceed with the operations below.

### 4. Start Trajectory Recording

1. Remotely drive the vehicle to the starting point of the recorded trajectory and mark the vehicle's heading and position at this time; you can draw a cross at the vehicle's front left wheel as a mark, as illustrated below:
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_3baaba6.png)

2. Click the **Record** button in the bottom operation bar to start trajectory recording.
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_ee5a170.png)

### 5. Stop Trajectory Recording

1. Use the remote controller to drive the vehicle along a stretch of trajectory (a straight line is recommended). After the vehicle stops, click the **Stop** recording button to stop record-and-replay recording.
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_ee5a170.png)

2. After stopping the trajectory recording, fill in the data package name in **Record Name** and click **Save**.
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_dd3fd3b.png)
   
   > Note: Naming rule restriction for the data package: the name may only consist of letters, digits and underscores.

## Step 3: Start the Record-and-Replay Driving Demonstration

1. Remotely drive the vehicle to the starting position used when recording the record-and-replay data in the sections above.
   
   At this time, a blue trajectory line is generated in front of the vehicle in Dreamview+; this trajectory line is the one just generated by the record-and-replay recording. Check that the generated trajectory line is clear and free of burrs, and confirm that the trajectory roughly matches the actual route. If they differ greatly, for example you recorded a straight drive but the trajectory shows a sharp turn, recheck the localization and record a new trajectory line.

> Note: Keep the starting position and heading of the vehicle as consistent as possible with those used when recording the trajectory.

2. Switch the remote controller to autonomous driving mode.

3. In Dreamview+, click the **START** button in the bottom operation bar to start autonomous driving.
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_b6bc07c.png)
   
   The vehicle starts record-and-replay and drives autonomously along the existing trajectory. Observe the vehicle's motion trajectory, including whether its speed, direction and so on are consistent with what was recorded earlier.
   
   ![image.png](https://bce.bdstatic.com/doc/Apollo-Homepage-Document/Apollo_Beta_Doc/image_aad3bd4.png)

> Note:
> 
> - While the vehicle is driving autonomously in record-and-replay, no perception-related sensors are used, so it will not brake or avoid when it meets obstacles; in an emergency, take over with the remote controller promptly. This is also why an open, closed site with few people and vehicles should be chosen.
> - The vehicle may start off quite abruptly; be ready to take over with the remote controller at any time, and in an emergency press the emergency stop button quickly.

4. After the vehicle finishes record-and-replay, take over with the remote controller promptly.

The specific symptom is that the vehicle issues throttle, steering and other signals but the chassis does not execute them, and no chassis-related information can be read either. The cause at this time should be that CAN is not connected. The solutions are as follows:

1. Check whether the CAN cable hardware is connected properly.

2. If step 1 is correct but the problem persists, check whether the `SocketCAN` startup script `start.sh` was started outside `docker` before starting canbus.

3. If step 2 is correct but the problem persists, check whether there are error messages in `apollo/data/log/canbus.INFO`.

4. If step 3 has been tried and the problem is still not solved, use a CAN debugging tool to see whether the chassis reports signals and whether commands are issued when apollo runs.

After opening `canbus.sh`, running `canbus_teleop.sh` can never enter autonomous driving mode, while the CAN debugging tool measures that the chassis signals are connected.

Open `/apollo/module/canbus/conf/canbus.conf`:
 Change `--receive_guardian` to `--noreceive_guardian`.

1. Check whether the `Dev_Kit` vehicle model is selected in `DreamView`; if you are unsure, first select another vehicle model and then reselect `Dev_Kit`.

3. Check whether the CAN driver was started correctly, that is, whether the `SocketCAN` startup script `start.sh` was started outside `docker` before starting canbus.

4. Check whether the hardware CAN cable interface is loose.
