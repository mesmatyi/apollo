Perception plugins come in two kinds: those in the object_filter_bank of lidar_detection_filter, and those in the roi_filter of pointcloud_map_based_roi.

The plugin mechanism is a dynamic loading mechanism that is more lightweight than components. Its purpose is to let developers focus more on the functional logic and extend functionality more conveniently. Plugin development is fairly independent, and plugins can be used flexibly by components, loaded as needed.
Take lidar_detection_filter as an example of plugin development. The object_filter_bank can run multiple filters, and all filters are placed in a std::vector<std::shared_ptr<BaseObjectFilter>>.

## Create a Folder

Create a new folder in the following directory, with the filter named new_filter, to hold the code and related configuration.

```bash
├── lidar_detection_filter

```

## Feature Definition

Implement the filter functionality.

First, inherit from the BaseObjectFilter class and implement Init (initialize configuration items), Filter (functional code), and Name (get the class name).

Then, at the end of new_filter.h, define: CYBER_PLUGIN_MANAGER_REGISTER_PLUGIN(apollo::perception::lidar::NewFilter, BaseObjectFilter). This indicates that this functionality is developed as a plugin.

```bash
class NewFilter : public BaseObjectFilter {
 public:
  /**
   * @brief Construct a new NewFilter object
   *
   */
  NewFilter() = default;
  virtual ~NewFilter() = default;

  /**
   * @brief Init of NewFilter
   *
   * @param options object filer options
   * @return true
   * @return false
   */
  bool Init(const ObjectFilterInitOptions& options =
                ObjectFilterInitOptions()) override;

  /**
   * @brief filter objects using new filter algorithm
   *
   * @param options object filter options
   * @param frame lidar frame to filter
   * @return true
   * @return false
   */
  bool Filter(const ObjectFilterOptions& options, LidarFrame* frame) override;

  /**
   * @brief Name of NewFilter object
   *
   * @return std::string name
   */
  std::string Name() const override { return "NewFilter"; }
 private:
   ... ...
 };

 CYBER_PLUGIN_MANAGER_REGISTER_PLUGIN(
    apollo::perception::lidar::NewFilter, BaseObjectFilter)
```

The specific functionality of the plugin is defined in the Filter function. This function receives the frame of the current point cloud frame, and the data in the frame mainly includes the following:

- The point cloud and its indices;

- The indices of non-ground point clouds and of point clouds within the roi;

- Detected obstacles (including model detections and background clustering);

- The pose from the lidar coordinate system to the world coordinate system;

- HD map information within a certain range of the ego vehicle.

lidar_detection_filter filters based on detected obstacles, and the filtering functionality is customized by the developer according to the actual situation.

## Plugin Management

First, the build in BUILD is as follows. A plugin must be built using apollo_plugin.

```bash
load("//tools:apollo_package.bzl", "apollo_package", "apollo_plugin")
load("//tools:cpplint.bzl", "cpplint")

package(default_visibility = ["//visibility:public"])

apollo_plugin(
    name = "libnew_filter.so",
    srcs = ["new_filter.cc"],
    hdrs = ["new_filter.h"],
    description = ":plugins.xml",
    deps = [
    ],
)
```

Then, create new_filter/plugins.xml and define in it:

```bash
<library path="modules/perception/lidar_detection_filter/object_filter_bank/new_filter/libnew_filter.so">
    <class type="apollo::perception::lidar::NewFilter" base_class="apollo::perception::lidar::BaseObjectFilter"></class>
</library>
```

## Using the Plugin

Once the plugin is defined, it can be used. To use it, add the configuration of this plugin to the configuration file modules/perception/lidar_detection_filter/data/filter_bank.pb.txt.

```bash
plugins {
    name: "ROIBoundaryFilter"
    config_path: "perception/lidar_detection_filter/data"
    config_file: "roi_boundary_filter.pb.txt"
}
plugins {
    name: "BackgroundFilter"
    config_path: "perception/lidar_detection_filter/data"
    config_file: "background_filter.pb.txt"
}
plugins {
    name: "NewFilter"  # Add the new_filter configuration here
    config_path: "perception/lidar_detection_filter/data"
    config_file: "new_filter.pb.txt"
}
```

After the new_filter plugin is configured, start the lidar_detection_filter component and run perception, and the configuration content of each plugin is loaded. When data comes in, new_filter executes the Filter function to complete the filtering.
