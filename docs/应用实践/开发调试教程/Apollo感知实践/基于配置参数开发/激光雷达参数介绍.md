## Parameter Directory Structure

First, the configuration directory of each component is introduced, using the LiDAR detection module as an example:

```bash
├── lidar_detection
    ├── conf            // Component configuration files
    ├── dag             // Component dag files
    ├── data            // Function configuration files
    ├── detector
    │   ├── center_point_detection
    │   ├── cnn_segmentation
    │   ├── mask_pillars_detection
    │   └── point_pillars_detection
    ├── interface
    ├── proto
    ├── lidar_detection_component.cc
    ├── lidar_detection_component.h
    ├── cyberfile.xml   // Package configuration file
    ├── README.md
    └── BUILD
```

Common configuration directory: the common configuration shared by multiple components is placed under the `modules/perception/data` path:

```bash
modules/perception/data
├── BUILD
├── conf    // Common perception configuration, e.g. some singletons
├── cyberfile.xml
├── flag    // All gflags of the perception module passed in on the command line, used by dag
├── models  // Model storage path
└── params  // Sensor intrinsics and extrinsics
```

### Modify the Configuration

Global configuration is modified in `/apollo/modules/perception/data/flag/perception_common.flag`. For example, to change the value of `obs_enable_hdmap_input` to false, you can add the following to the file:

```bash
--obs_enable_hdmap_input=false
```

The configuration of each component is in the conf and data directories of the corresponding component. Simply modify the values in the corresponding files directly. The 3D object detection module (lidar_detection) is used as an example.
