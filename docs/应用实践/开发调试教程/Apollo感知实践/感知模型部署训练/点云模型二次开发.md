Apollo currently provides the following lidar detection models: centerpoint, pointpillars, maskpillars, cnnseg.

To support users in deploying their own trained lidar detection models into apollo, this document takes the centerpoint model and the paddle3d open-source code repository as the basis to describe how users add a new model in apollo, including: installing paddle3d, an introduction to the training configuration, training, evaluation and export of centerpoint, and how to deploy centerpoint into apollo to see the results.

## CenterPoint Training

For the complete training workflow of centerpoint, refer to the AI Studio projects:

- [[Autonomous Driving in Practice] Lidar Object Detection Based on Paddle3D&amp;Apollo - PaddlePaddle AI Studio Community](https://aistudio.baidu.com/projectdetail/6778231)

- [[Perception Competition] Training CenterPoint with the ApolloScape Dataset - PaddlePaddle AI Studio Community](https://aistudio.baidu.com/projectdetail/7064946?contributionType=1)

### 2. Training Configuration Overview

Next, centerpoint_pillars_016voxel_kitti.yml is used as an example to describe the training configuration.

#### Basic Configuration

| Configuration  | Default Value | Meaning                                         |
| -------------- | ------------- | ----------------------------------------------- |
| batch_size     | 4             | Number of point cloud frames in a batch during training |
| val_batch_size | 1             | Number of point cloud frames in a batch during evaluation |
| epochs         | 160           | Number of epochs                                |

#### AMP Configuration amp_cfg

Automatic Mixed Precision (AMP for short) means using fp16 precision during training to increase computation speed and reduce storage space. For a detailed introduction, see [Automatic Mixed Precision Training (AMP)](https://www.paddlepaddle.org.cn/documentation/docs/zh/guides/performance_improving/amp_cn.html).

| Configuration           | Default Value | Meaning                                                     |
| ----------------------- | ------------- | ----------------------------------------------------------- |
| use_amp                 | False         | Whether to enable amp training                              |
| enable                  | False         | -                                                           |
| level                   | O1            | Mixed precision training strategy, options: O1, O2          |
| scalerinit_loss_scaling | 32.0          | Controls the loss scaling ratio, avoiding floating-point underflow |

### 3. Training Workflow

Next, the KITTI dataset is used as an example to train a CenterPoint model.

#### Data Preparation

1. First, download the relevant data from the [official website](https://www.cvlibs.net/datasets/kitti/eval_object.php?obj_benchmark=3d)
   
   - Download Velodyne point clouds, if you want to use laser information (29 GB)
   
   - training labels of object data set (5 MB)
   
   - camera calibration matrices of object data set (16 MB)

2. Download the dataset split file list:
   
   ```bash
   wget https://bj.bcebos.com/paddle3d/datasets/KITTI/ImageSets.tar.gz
   ```

3. After extracting the data, organize it according to the directory structure below:
   
   ```bash
   kitti_dataset_root
    |—— training
    |   |—— label_2
    |   |   |—— 000001.txt
    |   |   |—— ...
    |   |—— calib
    |   |   |—— 000001.txt
    |   |   |—— ...
    |   |—— velodyne
    |   |   |—— 000001.bin
    |   |   |—— ...
    |—— ImageSets
    │   |—— test.txt
    │   |—— train.txt
    │   |—— trainval.txt
    │   |—— val.txt
   ```

4. Under the Paddle3D directory, create a symbolic link `datasets/KITTI` pointing to the dataset directory above:
   
   ```bash
   mkdir datasets
    ln -s /path/to/kitti_dataset_root ./datasets
    mv ./datasets/kitti_dataset_root ./datasets/KITTI
   ```

5. Generate the ground-truth database required for data augmentation during training:
   
   ```bash
   python tools/create_det_gt_database.py --dataset_name kitti --dataset_root ./datasets/KITTI --save_dir ./datasets/KITTI
   ```
   
   `-dataset_root` specifies the path where the KITTI dataset is located, and `--save_dir` specifies the path used to save the generated ground-truth database. After this command is executed, the directory generated under `save_dir` is as follows:
   
   ```bash
   kitti_train_gt_database
    |—— anno_info_train.pkl
    |—— Car
    |   |—— 4371_Car_7.bin
    |   |—— ...
    |—— Cyclist
   ```

> Note: If you want to train with your own dataset, it is recommended to organize your dataset in the standard KITTI format.

#### Training

Training on the KITTI dataset uses 8 GPUs:

```bash
python -m paddle.distributed.launch --gpus 0,1,2,3,4,5,6,7 tools/train.py --config configs/centerpoint/centerpoint_pillars_016voxel_kitti.yml --save_dir ./output_kitti --num_workers 4 --save_interval 5
```

Training launch parameters:

| do_eval             | Whether to run evaluation when saving the model                                                    | No       | No            |
| log_interval        | Number of steps between log prints                                                                 | No       | 10            |

| model               | Fine-tune based on a pre-trained model                                                             | No       | .pdparam model file |

#### Evaluation

```bash
python tools/evaluate.py --config configs/centerpoint/centerpoint_pillars_016voxel_kitti.yml --model ./output_kitti/epoch_160/model.pdparams --batch_size 1 --num_workers 4
```

> Note: CenterPoint evaluation currently only supports a batch_size of 1. The evaluation launch parameters are as follows:

| Parameter    | Purpose                                                                                            | Required | Default Value |
| ------------ | -------------------------------------------------------------------------------------------------- | -------- | ------------- |
| batch_size   | Batch size per card                                                                                | No       | Value specified in the configuration file |
| config       | Configuration file path                                                                            | Yes      | -             |
| model        | Path of the model parameter file                                                                   | Yes      | -             |
| num_workers  | Number of processes for asynchronous data reading; child processes are used to read data when it is greater than or equal to 1 | No | 2 |
| quant_config | Quantization configuration file, generally placed under the [configs/quant](https://github.com/PaddlePaddle/Paddle3D/tree/develop/configs/quant) directory | No | None |

### 4. Model Export

Run the following command to export the dynamic graph model file saved during training into a static graph model file that the inference engine can load.

```bash
python tools/export.py --config configs/centerpoint/centerpoint_pillars_016voxel_kitti.yml --model /path/to/model.pdparams --save_dir /path/to/output
```

Export script parameters

| Parameter         | Purpose                                                                  | Required | Default Value  |
| ----------------- | ------------------------------------------------------------------------ | -------- | -------------- |
| config            | Configuration file path                                                  | Yes      | -              |
| model             | Model parameter path                                                     | No       | -              |
| export_for_apollo | Whether it is for Apollo deployment; when this switch is on, the meta file used for Apollo deployment is generated as well | No | False |

After the run is complete, the following files are output:

### 2. Deploy to Apollo and View the Results

For setting up the apollo environment, see the [perception 2.0 overview](https://apollo.baidu.com/community/article/1133).

#### Enter the Docker Environment

```bash
# Enter the container
aem enter

# Download and install dependency packages: this pulls and installs all the dependency packages in cyberfile.xml under the core directory
# It also automatically downloads the centerpoint model and places it in the specified location
buildtool build --gpu
```

The steps above deploy the official apollo centerpoint model. To deploy your own centerpoint model, just place the files exported in the previous step under `/apollo/modules/perception/data/models/center_point_paddle`:

```bash
|-- /apollo/modules/perception/data/models/center_point_paddle
    |-- apollo_deploy.yaml
    |-- centerpoint.pdiparams
    |-- centerpoint.pdiparams.info
    |-- centerpoint.pdmodel
```
