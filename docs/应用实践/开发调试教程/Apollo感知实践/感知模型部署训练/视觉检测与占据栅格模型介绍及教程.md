## 1. Introduction

In recent years, pure-vision + BEV object detection and occupancy grid tasks have become research hotspots in autonomous driving. The BEVFormer network proposed in 2022 uses surround-view images as input and uses a Transformer architecture to generate BEV features to complete the object detection task. The occupancy grid task expresses the real world by predicting a 3D grid. As shown in the figures below, a cell indicates that the corresponding position is occupied, and different colors represent different categories. The occupancy grid task can handle the irregularly shaped obstacle problem faced in autonomous driving well, and has therefore been widely studied.

![vision-detection-intro-1.png](./vision-detection-intro-1.png)

![vision-detection-intro-2.png](./vision-detection-intro-2.png)

Apollo 11.0 upgrades the pure-vision model Apollo-vision-Net, which has the following features:

1. [ _More advanced_ ] The mainstream perception paradigm of vision BEV object detection + occ occupancy network is introduced into the Apollo open-source framework, and Web-side OCC visualization is enhanced:
    * There is no need to run outside the local container environment. By connecting to the server via SSH, as long as the network is reachable, you can view OCC results directly in the Web interface.
    * An OCC element display function is added, providing richer visualization of scene information.
2. [ _Great results_ ] Optimized on top of classic industry models, each of its results surpasses those of the classic industry models. Object detection mAP is improved by _6.74%_ over bevformer (2022 ECCV), and occ miou is improved by _2.39%_ over OccNet (2023 ICCV). A model evaluation visualization comparison feature is added: it can output comparison charts of model evaluation results, and users can flexibly select and compare the evaluation results of different models or different training stages.
3. [ _High performance_ ] The model shares a backbone and is jointly trained and optimized across multiple tasks, reaching an inference frame rate of _5hz_ on a single _jetson orin_ platform, achieving a 1+1>2 effect in both quality and performance
4. [ _Ease of use_ ] Out-of-the-box engineering deployment: it provides a complete BEV perception solution, deployed on the Baidu Baige AI computing platform, offering a one-stop development workflow of model development, model training, model conversion and model export. It also adapts to Comate, the programming assistant driven by the ERNIE large model, providing developers with support for code generation, unit testing, comment generation, intelligent Q&A and more:
    * Model training: [Apollo-BEV-Train](https://console.bce.baidu.com/aihc/quickStart/detail?templateId=3928100)
    * Model export: [Apollo-BEV-Model-Export](https://console.bce.baidu.com/aihc/quickStart/detail?templateId=5599233)
    * Seamless model deployment to the Apollo environment: [Apollo-Model-Deployment](https://console.bce.baidu.com/aihc/quickStart/detail?templateId=9770074)

## 2. Introduction to Apollo-vision-Net

### Network Structure

The overall network structure of Apollo-vision-Net is as follows:

- Surround-view images are input, and the image backbone extracts image features
- Transformer encoder part
  - Temporal self-attention is used to fuse the current-frame bev queries and the historical-frame bev queries
  - Spatial cross-attention is used to fuse the bev queries and the image features
  - After 6 encoder layers, the bev queries are output
- detection head: takes the bev queries as input and uses the groupdetr network for object detection
- occ head: upsamples the bev queries, then expands the features in the height direction, and finally uses a linear layer to predict the category information of each cell

![vision-detection-vision-net-1.png](./vision-detection-vision-net-1.png)

We made the following optimizations to Apollo-vision-Net, which significantly improved the object detection and occupancy grid scores as well as model performance:

- image backbone: replaced ResNet-50 with DLA-34 pre-trained on depth estimation data (Toyota DDAD15M), which reduces model complexity while improving results
- image neck: replaced the single-scale FPN network with the SecondFPN network, improving the overall model results
- detection head: replaced DETR with GroupDETR, significantly improving object detection results without increasing latency
- occ head: low-resolution bev queries (50\*50) are used in the Transformer encoder part, and are then upsampled to high resolution (200\*200) in the occ head part, which greatly improves model performance
- occ loss: raised the occ focal loss weight from 1.0 to 10.0 and introduced the affinity loss and the lovasz-softmax loss, greatly improving occ detection results

### Quantitative Results

On the Nuscenes dataset, the object detection mAP score of Apollo-vision-Net surpasses bevformer-tiny (2022 ECCV) by _6.74%_ , and the occ result surpasses OccNet-R50 (2023 ICCV) by _2.39%_

|                            | Object detection mAP (val dataset) | Occupancy grid miou (OpenOcc val dataset) |
|:--------------------------:|:---------------------:|:------------------------------:|
| bevformer-tiny (2022 ECCV) | 25.2%                 | -                              |
| OccNet-R50 (2023 ICCV)     | -                     | 19.48%                         |
| Apollo-vision-Net (ours)   | 31.94% (↑ 6.74%)      | 21.87% (↑ 2.39%)               |

Run the following command, providing the pth file, to generate the onnx file

```bash
python tools/pth2onnx.py configs/apollo_bev/bev_tiny_det_occ_apollo_trt.py path_pth --opset_version 13 --cuda
```

### Deploy to apollo

Install the apollo environment according to the tutorial, then enter the container

```bash
bash docker/scripts/dev_into.sh
```

To replace it with your own trained onnx file, you need to replace the onnx file in the directory

```bash
sudo rm -rf modules/perception/data/models/apollo_bevnet_onnx/*
sudo cp your-own-onnx modules/perception/data/models/apollo_bevnet_onnx/
```

Then run the pure-vision model following the tutorial in Part 3
