planning-task-edge-follow-path
==============

## Introduction

`EdgeFollowPath` is used to generate an edge-following autonomous driving path. This task obtains the ego vehicle position through `Frame`, obtains lane information, reference line information and static obstacle information through `ReferenceLineInfo`, generates a Path by combining perception and map curb information, and finally outputs the computed path to `ReferenceLineInfo`.

### EnableEdgeFollow()
- This function checks whether edge-following path planning is allowed.

1. If the current reference line is not the rightmost lane, edge-following path planning is not performed.
2. If the `junction` area is considered and the vehicle is about to enter a `junction`, edge-following path planning is not performed.

### UsePerceptionEdge()
- This function determines whether to use the perception curb for edge-following path planning.

1. If the timestamp of the perception curb information differs greatly from the current timestamp, the perception curb information is not used.
2. If `is_useable` in the perception curb information is false, the perception curb information is not used.
3. Finally, the global parameter `FLAGS_disable_perception_edge_info` is checked to see whether perception curb information is disabled.
   
### DecidePathBounds()
- This function decides the path bounds the vehicle drives within (`candidate_path_boundaries`) by analyzing the surrounding lanes, the vehicle position and static obstacles.

It iterates over the decided side-pass directions (`decided_side_pass_direction_`) and tries to find path bounds for each direction.
`PathBoundsDeciderUtil::InitPathBoundary` is used to initialize the path boundary. The path boundary is updated according to the lane information and the ego position. The path boundary is updated again according to the projection of static obstacles onto the reference line.

This includes `ProcessEdgeFollowPathBounds()`, which processes the curb boundary.

### ProcessEdgeFollowPathBounds()
- Processes `path_road_boundary_` and computes the right curb boundary
  
1. If the perception curb is used, the path optimization sampling points are projected onto the right curb, or the road width on the right of each sampling point is used, to update `path_road_boundary_`.
2. Updates `path_boundary`, since it is used as the boundary for the QP solve.

### OptimizePath()
- This function is used to optimize the path. It receives two parameters: `candidate_path_boundaries` (path boundaries) and `candidate_path_data` (which stores candidate path data).

The function computes the path curvature constraint (`ddl_bounds`), the curvature rate of change (`jerk_bound`) and the reference path (`ref_l` and `weight_ref_l`).
It calls `PathOptimizerUtil::OptimizePath` to optimize the path. If the optimization succeeds, the computed path `path_data` object is added to `candidate_path_data`.

This includes the calculation of the towing point, `CalculateTowingDis()`, which computes the `L` value of the lateral towing and introduces it into the optimization cost, so that the path is pulled to the right side during optimization.

### CalculateTowingDis()
- This function is used to compute the towing point in the edge-following optimization, so that the path is pulled to the right side during optimization, achieving the edge-following effect.

The lateral towing `L` value, `towing_l`, is computed from the right boundary of `path_road_boundary_`, half the width of the ego vehicle, and the preset edge-following distance `FLAGS_edge_follow_buffer`.


### AssessPath()
This function is used to evaluate the candidate path data and select a final path.

The code iterates over the candidate path data. For each path data, the static function `IsValidRegularPath` of the `PathAssessmentDeciderUtil` class is used to check whether the path is valid. This checks whether the path is empty, whether the path is far from the reference line, whether the path is far from the road, whether the path collides with static obstacles, and whether the end of the path is in the adjacent lane in the opposite direction. `TrimTailingOutLanePoints` removes path points at the end of the road that are not in the ego lane. `ComparePathData` selects a suitable path according to factors such as road length, whether it borrows the opposite-direction lane, the ego lateral position, and returning to the ego lane sooner.

#### Usage

##### Configure and Load the EdgeFollowPath Task Plugin
In `modules/planning/scenarios/xxxx/conf/pipeline.pb.txt`, add the corresponding configuration in the scenario xxxx where you want to add the `EdgeFollowPath` plugin. In the configuration parameters, `name` is the name of the task, which is user-defined and only needs to make clear which task it is, and `type` is the class name of the task, i.e. `EdgeFollowPath`.
```
task {
  name: "EDGE_FOLLOW_PATH"
  type: "EdgeFollowPath"
}
```
##### Configure the EdgeFollowPath Parameters
In `modules/planning/tasks/edge_follow_path/conf/default_conf.pb.txt`, configure the parameters of the `EdgeFollowPath` plugin.
In `modules/planning/planning_component/conf/planning.conf`, configure the gflag parameters that act on the `EdgeFollowPath` plugin
##### Start planning
```shell
mainboard -d modules/planning/planning_component/dag/planning.dag
```
